## 需求 G1　图谱抽取状态可诊断、可重试（P0）

### 目标

让使用者在图谱页空白时，**10 秒内能自行回答三个问题**：现在卡在哪一步、为什么没有实体、点哪里能继续。图谱页不允许出现「只有一句安慰文案、没有任何可操作项」的空态。

### 用户故事

- 作为使用者，我看到视图 0 实体时，**想**立刻分辨这是「还没同步」「正在抽取」还是「全部失败」，**以便**不把系统故障当成正常等待。
- 作为使用者，我**想**看到每个失败对象叫什么、什么原因、什么时候失败的，**以便**决定是重试还是换模型。
- 作为使用者，我**想**一键重试失败或卡住的对象，**以便**不用删了重传、也不用整批重新同步。
- 作为使用者，我**想**知道当前用的是哪个模型、超时多久，**以便**判断「慢」是模型问题还是内容问题。

### 功能点

| # | 功能 | 要求 |
|---|------|------|
| 1 | 状态总览四数齐全 | 已进图谱总数、已完成抽取数、排队/抽取中数、失败数，四个数字同屏可见，不折叠 |
| 2 | 三种空态分流 | 0 实体时按原因给不同文案与动作：①未同步→「同步内容到图谱」；②抽取中→剩余数量 + 已等待时长 + 刷新；③全部失败→失败原因汇总 + 重试 + 「去配置大模型」入口 |
| 3 | 失败清单可识别 | 每条显示**对象标题**（不是 id 短码）、类型（作品/资产）、库别、失败时间、原因分类、原始错误（可展开） |
| 4 | 失败原因归类 | 至少区分：超时、连接失败、鉴权失败、服务端错误、内容解析失败、未知。归类映射到可读中文，原始错误保留在展开区 |
| 5 | 定向重试 | 单个失败对象「重试」；失败组「全部重试」；点后 30 秒内该对象变为排队/抽取中，计数相应减少 |
| 6 | 防重复入队 | 同一对象已在排队/抽取中时，重试按钮禁用并显示「排队中」；同一对象 1 分钟内最多触发 1 次 |
| 7 | 卡住判定 | `processing` 超过当前配置超时的 2 倍仍无进展 → 标记「可能卡住（已等待 X 分钟）」并提供重试 |
| 8 | 模型可见 | 状态区显示当前抽取模型名与超时值；全部失败且原因均为超时时，给出「本机模型较慢，可切换外部 API」并链到 M1 页面 |
| 9 | 刷新不打断 | 「刷新进度」只更新状态与计数，不重置当前中心实体、视图模式（3D/2D）、缩放与选中 |

### 边界与异常

- **失败原因为空**：显示「服务未返回原因（状态码 X）」，不得留白。
- **LightRAG 不可达**：整页显示「图谱服务未连接」+ 诊断入口，**不允许**显示 0 实体并提示「抽取完成后会出现」，这会误导用户以为在正常排队。
- **重试的语义**：只重新提交抽取，**不修改对象本身、正文与归属**；重试不产生重复对象、不产生重复内容引用。
- **权限**：查看诊断 = 读权限；重试 = 图谱写入权限（沿用 ADR-019 体系）。无权限时按钮不渲染，接口仍返回 403 并记审计。
- **审计**：每次重试记一条（谁、哪个对象、当时的模型与超时、结果）。批量重试记 1 条汇总 + N 条明细。
- **主题**：新增的状态块、失败列表、警告徽标在 4 套主题下都必须可读，对比度沿用主题验收口径（正文 ≥4.5:1，边框/焦点 ≥3:1）。
- **规模**：失败对象 200 条时列表可滚动且页面不卡；不要求虚拟滚动，但不得一次请求拉全文。

### 验收标准（可点检）

1. 制造 1 个超时失败对象后打开 `/graph`：状态区同时显示「已进图谱 4 个 / 失败 1 个」，展开失败清单能看到该对象的**标题**、原因「超时」、失败时间，展开后能看到原始错误文本。
2. 当所有对象都失败时，0 实体空态的标题是「全部抽取失败」而不是「抽取完成后会出现实体」，且页面上有「重试」与「去配置大模型」两个可点击入口。
3. 点某个失败对象的「重试」→ 30 秒内该对象状态变为「排队中/抽取中」，失败数 −1；按钮变为禁用并显示「排队中」，再点无效。
4. 把 1 个对象的 `processing` 停留在超过 2× 超时 → 清单出现「可能卡住（已等待 X 分钟）」与重试按钮（可用测试数据或调小超时构造）。
5. 点「刷新进度」后，当前选中的中心实体、3D/2D 模式、缩放比例均不变化，仅状态数字更新。
6. 以无写权限账号登录：看不到任何重试按钮；直接调用重试接口返回 403，且审计里多一条 `result=denied`。
7. 停掉 LightRAG 后打开图谱页：显示「图谱服务未连接」，不显示 0 实体空态。

### 优先级与依赖

- **P0**：当前状态已经是坏的，用户无法自救。
- 依赖 M1 的页面路由（仅作跳转目标）；依赖 ADR-019 权限；不得回归 ADR-022 的 3D/2D 视图行为。

### 明确不做

- 不自动重试、不自动切换模型（v1 全部手工，避免外部 API 费用失控）。
- 不做百分比进度或逐 chunk 进度（LightRAG 不提供，不假装有）。
- 不做失败原因的词典后台（固定分类即可）。
- 不做失败报告导出、不做邮件/消息告警（v2 再议）。
- 不改 LightRAG 内部排队与并发策略。

## 需求 M1　「系统 → 大模型」配置入口（P0）

### 目标

管理员能在界面里把图谱抽取模型从本机慢模型换成**任意 OpenAI 兼容端点**，并且换的过程安全：先测试、再启用、可回滚、密钥不泄露、不出现「显示成功但实际没生效」。

### 用户故事

- 作为管理员，我**想**把抽取模型换到外部 API，**以便**把「几十分钟」的抽取降到「几分钟」。
- 作为管理员，我**想**在保存前先测通连接，**以便**不把本来能用的抽取弄坏。
- 作为管理员，我**想**新配置出问题时一键回到上一份能用的配置，**以便**随时止损。
- 作为管理员，我**想**确认配置真的生效了（哪个模型、什么时候生效），**以便**不靠猜。
- 作为编辑/只读用户，我**不应该**看到密钥或改动配置。

### 入口与位置

- 位置：第一列导航「系统」→ 第二列目录内，与「系统状态」「审计日志」同组，新增一项「大模型」。
- 路径：建议 `/admin/models`（最终以 Architect / Designer 的导航方案为准，但**必须只有一个入口**，不在第一列导航再加第二项）。
- 可见性：拥有「模型配置读」权限的角色可进入查看（密钥始终脱敏）；拥有「模型配置写」权限才能测试、保存、启用、回滚。权限 key 的命名由 ADR-019 体系扩展，交给 Architect。

### 功能点

| # | 功能 | 要求 |
|---|------|------|
| 1 | 配置表单 | 显示名（备注，可选）、Base URL、模型名、API Key、超时（秒，30–600，默认 300）、最大并发（1–8，默认 1，v1 可只读展示） |
| 2 | 供应商范围 | 任何兼容 `POST {baseURL}/chat/completions` 的端点：OpenAI、DeepSeek、Moonshot/Kimi、通义兼容模式、硅基流动、自建 vLLM / Ollama 的 `/v1` 等。提供 3–4 个常见预设按钮一键填 Base URL 与示例模型名，**预设只填表、不锁定**，可手改任意字段 |
| 3 | 测试连接 | 用当前表单值发一次最小请求，30 秒内返回三态：成功（回显模型名 + 耗时）/ 失败（HTTP 状态 + 服务端错误摘要）/ 超时。**测试不写入任何配置、不影响正在跑的任务** |
| 4 | 保存与生效 | 「保存并启用」必须先测试通过；测试不过只能「存为草稿」。生效对象是**新发起**的抽取；已在抽取中的任务不被中途换模型。页面必须明写「已于 HH:MM 生效 · 模型 X」以及「进行中的 N 个任务仍使用旧模型」 |
| 5 | 密钥只写不回显 | 保存后页面只显示 `sk-••••abcd`（后 4 位）；所有读接口都不回传明文；替换需重新输入；清空密钥需二次确认。界面、日志、错误信息里都不得出现明文 |
| 6 | 回滚 | 保留「最近一次启用成功」的配置快照，一键回滚并立即生效；同样不打断进行中任务。保留最近 5 条变更记录（时间、操作人、模型、Base URL、超时、结果），**不含密钥** |
| 7 | 失效提示 | 启用后若连续 3 次抽取因鉴权或连接失败，系统状态页与图谱页给出「当前模型配置可能失效」提示与「去大模型页检查」入口；**不自动回滚**（v1 手工） |
| 8 | 计费提示 | 页面固定一行提示：使用外部 API 会产生费用、消耗你自己的额度。不做用量统计与预算控制（明确列为不做） |
| 9 | 主题与无障碍 | 4 套主题下表单、状态徽标、错误提示一致；每个字段有 label、错误与输入关联、Tab 顺序完整、Esc 不误关已填表单（有未保存改动时二次确认） |

### 边界与异常

- **谁能配置**：仅 owner / admin 级角色（v1）。无权限：目录整组不渲染，直链 403，接口 403 且记审计。
- **密钥存储**：存储方式与加密由 Architect 定，但需求硬约束两条——①数据库文件被拿走时密钥不可直接可用（至少不明文落库）；②导出、备份、日志、错误上报里不含密钥。
- **生效机制**：若实现上需要重启或重载 LightRAG，页面必须如实显示「需重启，预计 X 秒」以及排队任务的处置方式（保留排队 / 失败后可重试），**不得出现保存成功但实际没生效**。
- **外部端点异常分类**：DNS 解析失败、连接被拒、401/403 鉴权、404 模型不存在、429 限流、5xx 服务端、读取超时，分别给不同的中文提示与建议动作。
- **配置写坏**：任何保存/启用/回滚都必须能在失败时保持原配置不变（原子性），不允许出现「一半新一半旧」。
- **多环境**：本机 `AUTH_MODE=mock` 与 Logto 两种模式下页面行为一致；mock 下同样要求权限判定（不能因为是 mock 就跳过）。
- **Embedding 不在本页**：向量模型仍是本地 bge，换它会触发全量重算，单独需求，本页不提供入口也不暗示可改。

### 验收标准（可点检）

1. 填入一个错误 Key 点「测试连接」：30 秒内显示「鉴权失败（401）」；配置**没有**生效，随后发起的一次抽取仍使用旧模型（图谱页状态区模型名不变）。
2. 填入可用外部端点测试成功 → 「保存并启用」→ 页面显示「已启用 · 模型 X · HH:MM」；随后新发起一次抽取，图谱页状态区显示的模型名变为 X。
3. 保存后刷新页面并调用读取接口：API Key 只出现 `••••abcd` 形式；在页面源码、网络响应、应用日志中检索完整 Key 字符串，结果为 0 处。
4. 启用一份坏配置（如 baseURL 指向不可达地址）后点「回滚」：配置恢复为上一份可用值，再抽取一次成功，状态区模型名回到旧模型。
5. 无权限账号访问 `/admin/models` 直链 → 403 说明页；直接调用保存/启用的接口 → 403，且审计有 `denied` 记录。
6. 分别切换 4 套主题打开本页：无硬编码颜色、无错位、正文对比度 ≥4.5:1、焦点环可见。
7. 变更记录能查到最近 5 次操作（时间/操作人/模型/结果），任意一条展开后都不含密钥明文。
8. 在「有未保存修改」状态下按 Esc：先出现「放弃修改？」确认，取消后表单内容不丢。

### 优先级与依赖

- **P0**：是 G1 的根因解决方案，也是用户明确要求的自助入口。
- 依赖 ADR-019 权限体系；依赖 ADR-010「LightRAG 是唯一外部入口」；需要 **Architect 新出 ADR**（配置存放、密钥加密、生效机制、回滚语义）。

### 明确不做

- 多用户各自的模型配置（单机单配置，全局一份生效）。
- 按任务/按库选择不同模型、多配置 A/B 或路由。
- Embedding / rerank / 向量模型配置。
- 用量统计、费用预算、余额查询、自动降级到便宜模型。
- 非 OpenAI 兼容的原生协议（Anthropic / Gemini 原生 SDK）。
- temperature / top_p / max_tokens 等推理参数暴露到界面（v1 用合理默认）。
- 密钥轮换提醒、密钥共享、密钥权限分级。

## 需求 P1　点击对象弹出内容预览（P0）

### 目标

在工作台（以及检索结果、后台内容页）点击任意作品或资产，**不离开当前列表**就能看到具体正文与解析状态；需要编辑时再进详情。

### 用户故事

- 作为使用者，我**想**点一条作品就弹出正文，**以便**确认解析出来的内容对不对，而不是先跳详情再找。
- 作为使用者，我**想**在弹窗里看到解析状态与失败原因，**以便**知道为什么检索里搜不到它。
- 作为使用者，我**想**在看完后一键进详情编辑，**以便**预览只读、修改另开，不会误改。
- 作为使用者，我按返回键就能回到列表原来的位置，**以便**连续查看多条。

### 功能点

| # | 功能 | 要求 |
|---|------|------|
| 1 | 触发 | 点击列表行的标题或行主体打开弹窗；行内勾选框、批量操作、菜单按钮的行为不变（不得误触） |
| 2 | 弹窗头部 | 标题、类型（作品/资产）、分类（形态）、标签、库别、作品状态、更新时间、解析状态徽标 |
| 3 | 正文渲染 | Markdown → 渲染后的富文本（只读，复用 ADR-014 渲染器）；纯文本 → 原样等宽显示；PDF → 内嵌浏览器查看器（可翻页/缩放）；图片 → 直接显示；其他附件（docx/xlsx/zip 等）→ 文件名 + 大小 + 下载按钮 |
| 4 | 主内容与附件 | 有多个文件时可切换查看；标明哪个是主内容 |
| 5 | 解析状态 | 徽标 + 说明；失败时显示原因与「打开详情处理」；解析中显示「解析中，不影响正文预览」 |
| 6 | 操作 | 打开完整详情、下载、编辑（有权限且可编辑类型时）；**不在弹窗内保存编辑** |
| 7 | 关闭与返回 | 关闭按钮、Esc、点遮罩三种方式都能关；关闭后焦点回到触发行；浏览器返回键关闭弹窗且列表筛选与滚动位置不丢 |
| 8 | 可达性 | `role="dialog"` + `aria-modal` + 以标题为可访问名；焦点锁定在弹窗内；Tab 不会跑到背后页面 |
| 9 | 移动端 | 近全屏 sheet，正文可滚动，头部操作固定但不遮正文 |
| 10 | 性能 | 打开 ≤1 秒显示元数据与骨架；正文按需加载，不拖慢列表；图片/PDF 懒加载，同时只加载一个预览 |
| 11 | 主题 | 4 套主题一致；容器与文字走语义 token；PDF/图片自身白底视为文档内容，允许例外并在代码注释里标注 |

### 边界与异常

- **无内容**：显示「尚未上传内容」+ 上传入口（有权限时），不是空白面板。
- **内容文件缺失**：显示「内容文件不存在（可能已被替换或删除）」+ 打开详情，而不是静默空白或一直转圈。
- **超大文件**：沿用现有 25MB 上传上限；超过预览阈值的直接给下载（阈值由 Designer 定，但必须有阈值和明确提示）。PDF 过大时不内嵌，只给下载。
- **加载失败/断网**：正文区显示「加载失败，重试」，元数据仍然可见。
- **安全**：Markdown 渲染沿用 ADR-014 的安全策略（不执行脚本、不加载未知外链资源）；PDF 用浏览器原生查看器，不引入第三方在线渲染服务；附件下载保持现有权限判定。
- **权限**：读预览沿用对象读权限；无权限时 403 文案，不泄露标题以外的信息。
- **不改数据**：打开预览不修改 `updatedAt`、不产生审计噪声（预览是读操作）。

### 验收标准（可点检）

1. 在工作台列表点一条 Markdown 作品的标题 → 弹窗打开，正文渲染正确（标题、粗体、列表、行内代码与编辑器预览一致）；点击行内勾选框不会打开弹窗。
2. 按浏览器返回键 → 弹窗关闭，列表恢复原来的筛选条件与滚动位置；焦点回到刚才那一行。
3. 点一条 PDF 资产 → 弹窗内能直接翻页查看，无需先下载；点一条 30MB 附件 → 不内嵌，显示大小、「文件过大，请下载查看」与下载按钮。
4. 点一条解析失败的对象 → 显示「解析失败」徽标与失败原因；若正文存在仍可预览；有「打开详情处理」入口。
5. 点一条无内容对象 → 显示「尚未上传内容」（有权限时含上传入口），不是空白。
6. 用键盘操作：打开后 Tab 只在弹窗内循环，Esc 关闭并回到触发行；读屏能读出弹窗标题。
7. 4 套主题各打开一次：无错位、无不可读文字、无硬编码背景（PDF/图片内容除外）。
8. 预览一条 3MB Markdown 后，列表滚动与筛选操作无可感知卡顿；同一时刻只存在一个预览请求。

### 优先级与依赖

- **P0**：这是用户日常最高频的动作，且当前「内容在哪看」已经造成困惑。
- 依赖 ADR-014 的 Markdown 安全渲染；依赖现有内容区数据（主内容/附件、解析状态）；与 ADR-019 权限打通。

### 明确不做

- 弹窗内编辑与保存（编辑仍进详情页；v1 只读预览）。
- Office 文档在线渲染（docx / xlsx / pptx 一律下载）。
- 视频、音频播放器（v1 下载；v2 再评估）。
- 多对象并排对比、拖拽分屏。
- 检索命中高亮、定位到正文第 N 段（v2）。
- 弹窗内「上一篇/下一篇」连续阅读。
- 离线缓存、全文索引预览。

## 跨需求的全局约束

| 项 | 约束 |
|----|------|
| 权限 | 三项新增的读/写能力全部挂 ADR-019 的 `requirePermission`；UI 隐藏只是体验，不是安全边界；每条新路由都要进全路由覆盖测试 |
| 主题 | 新增页面与弹窗不得出现裸色值；4 套主题（含深空）一致；纳入现有样式审计；用户已明确「主题切换时要保持一致」 |
| 审计 | 模型配置的测试/保存/启用/回滚、抽取重试都要落审计；预览属于读，不落审计 |
| 错误可读 | 所有错误给中文分类 + 可执行下一步，不出现空白原因或纯英文堆栈 |
| 文案 | 面向使用者的界面不用 payload / trigger / endpoint 之类的工程词，用「接口地址」「模型」「超时」 |
| 文档同步 | 落地后需更新 `06_API.md`、`09_USER_GUIDE.md`、`05_CHANGELOG.md`（由 Docs 负责，不在本需求内） |
