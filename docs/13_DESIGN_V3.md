### 0.3 关键术语

- **分类（Category）**：用户可见名称。内容归到哪一类，例如文章、课程、直播。**单选**，属于结构字段。内部表 `categories`、对象列 `objects.category_code`、领域与 API 字段 `category`（ADR-023 已定稿，见 §6.0.1）。
- **标签（Tag）**：内容属性，例如工具类、感悟类、技巧经验类。**多选**，用于跨分类的内容归类，属于描述字段。
- **词表（Taxonomy）**：分类与标签的统称。全站只有一份，任何页面增删改都读写同一数据源。

### 0.4 硬约束

- **默认主题观感零变化**：松林绿的所有取值与现有 `globals.css:1-81` 完全一致。
- **对比度**：正文 ≥ 4.5:1，大字 ≥ 3:1，非文字控件边界 ≥ 3:1，焦点环 ≥ 3:1。所有新主题实测值见 §3.3。
- **触控**：移动端可点区域 ≥ 44×44；桌面端 ≥ 32×32。
- **焦点**：所有可交互元素有 `:focus-visible`，焦点环 2px + 2px offset。
- **动效**：`prefers-reduced-motion: reduce` 时全部降级；不引入动画库。
- **依赖**：默认不新增 UI 库、图标库、动画库、粒子库；首页星系用原生 Canvas 2D 单画布（ADR-018），不引 WebGL。唯一例外候选是 next-themes（~1.5 KB，只做主题持久化与防闪烁，需 Architect 批准，见 §0.5 / §3.5）。
- **单一真相**：分类与标签不在任何页面维护本地副本；管理页、弹窗、筛选、详情读同一份词表。

## 1. 「新建内容」弹窗改版

### 1.1 视觉说明

现有弹窗是一个 580px 的单列表单，分类是 6 个等宽 chip，没有标签区，分类也不可扩展（`create-object-dialog.tsx:227-249`）。改版目标是**让“结构”和“属性”在视觉上分层**：

- 分类用**单选 chip**：横向排列、等宽、带选中勾，像“选择归到哪一类”。
- 标签用**多选 chip + 输入框**：已选标签在上、输入与建议在下，像“给内容贴属性”。
- 两者之间用**分组标题 + 16px 间距**分隔，不靠颜色区分；标签不使用彩色分类，避免出现“彩虹标签”。
- 「管理」入口放在分类标题行右侧，是次级文字链接，不抢主流程。

弹窗从上到下分两套顺序，**标签始终紧跟它所属的内容属性区**（Phase 6 已统一为「分类 → 标签」，见 §6.3）：

- 作品：**类型 → 标题 → 分类 → 标签 → 放在哪里 → 说明 → 底部操作**。
- 资产：**类型 → 标题 → 分类 → 标签 → 放在哪里 → 说明 → 底部操作**。

分类是内容属性，资产与作品都需要；资产不再把标签放到库别之后。

### 1.4 分类区（第一版方案，已被 §6.1 / §6.2 取代）

> 以下是 v1.0 的「网格 + 就地新增」方案，保留作对照；落地一律按 §6.1 的「候选区 + 自定义弹窗」。用户可见「形态」已统一为「分类」；内部字段按 ADR-023 改名为 `categories` / `objects.category_code`（§6.0.1）。

**结构**：

```
分类            单选 · 决定内容归到哪一类              ⚙ 管理
[文章] [音视频脚本] [课程]
[直播] [咨询] [外部笔记] [＋ 新增分类]
```

**样式**：

- 标题行 `display:flex; align-items:center;`；「管理」是 `<a>`，字号 12，颜色 `--text-2`，带 14px settings 图标；hover 变 `--accent-strong` 并加下划线；点击在新标签页打开 `/admin/vocabulary/categories`，**不丢失当前填写**。没有 `vocabulary:category:write` 时隐藏「管理」；只读用户隐藏「自定义」。
- chip 高 38px、3 列等宽、字号 13、文字居中、圆角 10px、1px `--line`（§6.1 改为 34/44，以 §6.1 为准）。
- 选中：底 `--accent-050`、边框 `--accent`、内描边 1px、文字 `--accent-strong`、字重 600，左侧出现 14px 勾选图标（勾在文字前，gap 6px）。
- 未选中 hover：边框 `--accent`、文字 `--text-1`。
- 按下：`transform: scale(0.98)`，120ms。
- 焦点：`outline: 2px solid var(--focus); outline-offset: 2px`。
- 新增 chip：虚线边框 `1px dashed var(--line-strong)`、文字 `--text-2`、左侧 14px 加号；hover 边框变实线 `--accent`、文字 `--accent-strong`。
- 新增交互（**已被 §6.2 取代**）：点击后就地变成同尺寸输入框（占一个网格单元），placeholder「新分类名称」，右侧出现确认 ✓ / 取消 × 两个 24px 图标按钮。Enter 确认、Esc 取消、失焦且非空时确认；成功后新 chip 插入「新增」之前并自动选中；失败则在网格下方显示 12px 危险色错误，输入值保留。新增项与标签一样**先暂存、随表单提交写入全局词表**，取消弹窗不留下 0 使用量词条；写入失败则整单失败、保留输入。
- 词条规则（对齐 R1）：1–12 个字符；去首尾空格；不能为空白或纯符号；归一化后全局唯一（忽略大小写）；最多 30 个启用分类。
- 超长分类名：输入上限 12 字，chip 单行显示；历史超长数据用 `text-overflow:ellipsis` + `title`。
- 空状态（全部停用）：显示一行 13px `--text-3`「还没有可用分类，先添加一个」，下方只保留「＋ 新增分类」。
- 排序：默认 6 项固定顺序；自定义项按管理页 `sort_order` 追加；弹窗内不提供拖拽，避免误操作。

**为什么不做多选**：分类是作品的结构字段（`WorkObject.category`），多选会破坏现有筛选、图谱与状态流转的语义。ADR-023 已定**单选**；将来若确需多分类，按 ADR-023 第 2 条新增 `object_categories` 关联表并另开 ADR，本文不预留半套多值结构。

**范围说明**：弹窗内新增是管理页新增的快捷入口，调用同一服务、写同一张 `categories`，不另设本地词表；只读用户去掉「＋ 自定义」入口，布局与其余规则不变。

### 1.5 标签区（新增；交互已被 §6.1 取代）

> v1.0 的「输入框 + 建议面板 + 回车创建」方案保留作对照；落地按 §6.1 的 `TagField`（多选候选 + 自定义弹窗）。**新标签改为立即落库**：ADR-023 收紧后，服务端不再接受保存时隐式建标签（`TAG_NOT_FOUND`），见 §6.0.2 的说明。

**结构**：

```
标签  内容属性，可多选                             3/10
[工具类 ×] [技巧经验 ×] [感悟 ×]
[ 输入标签后回车，或从下方选择…                    ]
```

**样式**：

- 已选 chip：高 26px、padding `4px 10px`、圆角 pill、底 `--green-050`、边框 1px `--green-100`、文字 12/500 `--green-700`；右侧 × 按钮 16px，点击区 24×24（移动端 32×32）。
- chip hover：底 `--green-100`；× hover：文字 `--danger-fg`。
- 输入框：高 40px，左侧 16px `#` 或标签图标（可选），字号 13；placeholder「输入标签后回车，或从下方选择…」。
- 建议面板：从输入框下方展开，宽 100%，最大高 176px，圆角 12px，`--surface` 底、`--shadow-pop`、1px `--line`；每行 32px，左名称 13、右使用次数 11 `--text-3`；当前行底 `--green-050`、左侧 2px `--green-600`。
- 无匹配时首行显示「＋ 创建标签「xxx」」，回车即创建并选中。
- 已选 10 个后：输入框禁用，placeholder「最多选择 10 个标签」，右侧计数变 `10/10` 并使用 `--text-3`。
- 空词典：已选区不显示；输入框下方常驻一行 12px `--text-3`「还没有标签，输入第一个标签回车即可创建」+ 3 个推荐 chip（工具类 / 感悟类 / 技巧经验类），点击直接选中。
- 重复标签：不新增，已存在 chip 播放 600ms 的 2px `--green-600` 外环，并显示 12px 提示「已添加过这个标签」。
- 新标签不立即写库：随表单提交一起写入；服务端在同一事务里按归一化键 upsert `tags`，再写 `object_tags` 关联，取消弹窗不留下 0 引用的孤儿词条。
- 标签规则（对齐 R2，全站前后端同一份归一化实现）：1–20 个字符；按 `,` `，` `、` 和回车分隔；去首尾空格、连续空格折叠为一个；NFKC 归一化后比较（全角/半角视为同一）；比较时忽略英文大小写，展示保留首次创建的写法；不允许以 `#` 开头；允许中英文、数字、`-`、`_`、空格；同一对象内归一化后相同则去重，不报错；单对象最多 10 个；全局词表软上限 500（超出只提示合并，不阻塞）。
- 长标签换行：chip `max-width:100%`、`white-space:normal`、`overflow-wrap:anywhere`、`line-height:1.35`；最多 2 行，超过用 `-webkit-line-clamp:2` + `title` 显示全文。输入上限 20 字，正常情况单行；该规则用于历史导入数据。
- 键盘：Enter 或 `,` `，` `、` 添加并清空输入；Backspace 在输入为空时删除最后一个 chip；↑↓ 在建议中移动；Esc 先关建议面板，再按一次关弹窗。

**为什么标签不能和分类共用一套 chip**：分类是单选、有且只有一个；标签是多选、可增删、可新建。控件形式必须不同，否则用户会误以为分类也能多选。（Phase 6 起两者共用同一套候选区骨架 `PickerShell`，但组件、选中图形与计数各自独立，见 §6.1。）

### 1.6 放在哪里 / 说明

- 说明 textarea 最小 88px，placeholder「补充来源、用途或下一步计划…」，右下角显示 `0/5000` 计数（仅聚焦时出现）。

### 1.7 校验与错误位置

| 场景 | 位置 | 表现 |
|---|---|---|
| 标题为空 | 标题字段下方 | 12px `--danger-fg`，图标 14，输入框边框变 `--danger-fg`，`aria-invalid="true"`，焦点移到标题 |
| 标题超长 | 同上 | 输入框 `maxLength=200`，超出不允许输入；计数 `200/200` 变危险色 |
| 分类未选 | 分类区下方 | 作品默认选中排序第一的启用分类；若被清空，提示「请选择一个分类」 |

### 2.4 全局同步契约（设计层）

- **唯一数据源**：`categories`、`tags`、`object_tags` 三张表（见附录 A.2 与 ADR-023）。分类选项、标签建议、筛选列表、详情徽标全部从同一组接口读，页面不缓存选项副本。
- **改名为什么即时全站生效**：对象只存 `objects.category_code`（分类 code）和 `object_tags`（标签 id），**不存名称**。改名是一次单行 `UPDATE`，下一次读取自然拿到新 label，不需要回填任何对象，也不会出现“某页还是旧名字”。
- **合并为什么即时生效**：合并只把 `object_tags.tag_id` 从源指向目标（撞上同对象已有目标标签的重复关联直接丢弃），再删源词条；`objects` 行不动。所有列表、筛选、详情都读关联表，因此一次事务后全站一致。
- **使用次数**：由数据库聚合，不由前端累加；管理页与弹窗同源。软删对象行仍在、外键级联不会触发，所以每次统计都必须显式排除 `deleted_at`：

```sql
-- 标签使用数：软删对象不计入
SELECT t.id, COUNT(o.id) AS usage
FROM tags t
LEFT JOIN object_tags ot ON ot.tag_id = t.id
LEFT JOIN objects o ON o.id = ot.object_id AND o.deleted_at IS NULL
GROUP BY t.id;

-- 分类使用数：统计全部未删除对象（资产也计入），软删排除
SELECT c.code, COUNT(o.id) AS usage
FROM categories c
LEFT JOIN objects o
  ON o.category_code = c.code AND o.deleted_at IS NULL
GROUP BY c.code;
```

- **写入即刷新**：管理页保存后 `router.refresh()`；服务端 `revalidateTag("taxonomy")` + `revalidatePath("/workspace")`、`("/search")`、`("/admin")`（对齐 R3）；其他已打开页面在下一次导航/刷新时拿到新值。
- **乐观更新 + 回滚**：重命名、停用、排序先在本地更新，请求失败回滚并 toast「保存失败，已恢复」。
- **删除保护**：`object_tags` 用外键兜底（硬删对象或标签时关联级联清理）；软删对象不触发级联，关联保留但计数排除。有引用的标签删除返回 409，只允许「合并」或「同时从 N 个对象移除」；有引用的分类只允许停用或迁移。
- **权限**（ADR-023 / ADR-019）：读取对所有登录用户开放（新建/筛选要用）；**内联新增**分类 / 标签向 `object:write` 开放（普通编辑者也能加，见 §6.2）；改名、排序、停用、删除、合并、迁移需要 `vocabulary:category:write` / `vocabulary:tag:write`。没有管理权限时看不到管理入口，直链访问得到 403（见 §2.2）。

## 4. 银河首页

### 4.1 概念与层级

首页只做一件事：**让用户从一个问题开始**。视觉是银河，但信息层级只有三层：

1. **搜索**（唯一主任务）：正中偏上的玻璃搜索框。
2. **入口**（次级）：左侧收起的三角把手 → 工作台抽屉。
3. **身份/状态**（辅助）：顶部品牌与右上角进入工作台；底部一行本地保存说明。

星系是背景，不是内容；不做卡片堆叠、不做数据概览、不做轮播。首页固定使用「深空银河」视觉（品牌场景），不随工作台主题切换；搜索框与抽屉的强调色可跟随当前主题 `--accent`，但背景星空不变。

**路由**：`/`。登录用户直接可用；未登录用户看到同一页面，搜索框禁用并提示「登录后可检索内容」，右上角显示登录入口。旧 `welcome-page.tsx` 已由 `galaxy-home.tsx` 取代。

### 4.5 背景参数

**底色**：

**星云**：

  filter: blur(60px);

.nebula-b {
  background: radial-gradient(closest-side, rgba(8, 145, 178, .16), transparent 70%);
  filter: blur(60px);
}
```

**星系（Canvas 2D 单画布，ADR-018）**：

- 一个全屏 `<canvas>`，尺寸 = 视口 × DPR（DPR 上限见 §4.9），`ctx.globalCompositeOperation = 'lighter'` 做叠光；不创建 WebGL 上下文，也不加第二个画布。
- 1600 个粒子（移动端 900），初始化时全部预计算进 `Float32Array`：`r`、`arm`、`jitter`、`size`（1–2.4px）、`brightness`（0.4–1）、`phase`、`x0`、`y0`。
- 螺旋公式与数值完全不变，只是改为逐粒子 2D 绘制：
  - `θ0 = arm * π + r * 4.2 + jitter * 0.35 * (1.0 - r)`
  - `x0 = cos(θ0) * r * R`，`y0 = sin(θ0) * r * R * 0.42`（盘面压扁）
  - 每帧旋转角 `a = t / 240s * 2π`：`x = x0 * cos(a) - y0 * sin(a)`，`y = x0 * sin(a) + y0 * cos(a)`；再套用整体 `-24°`（它的 cos/sin 也预计算）。
- 每帧只算一次全局 `cos(a)` / `sin(a)`，粒子层只有四则运算，不做逐粒子三角函数；`baseAlpha = smoothstep(1.0, 0.1, r) * brightness` 在初始化时算好。
- 颜色：核心 `#f1f5f9` → 旋臂 `#67e8f9` / `#a78bfa` 按 `r` 混合；绘制用三张预渲染的径向渐变 sprite（白 / 青 / 紫），`drawImage` 按粒子 `size` 缩放，避免每帧创建渐变对象。
- 闪烁：每颗粒子带固定 `phase`，亮度在 ±15% 内以 2–4s 周期起伏；`prefers-reduced-motion` 时固定为 1.0。只影响 alpha，不改变位置与颜色。
- 旋转：360° / 240s（1.5°/s）；`prefers-reduced-motion` 时渲染一帧静态画面后停止 rAF。
- 核心辉光单独用 CSS：`radial-gradient(circle, rgba(226,232,240,.18), transparent 70%)`，220×220，轻微呼吸 6s（reduced-motion 关闭）。
- 盘面椭圆：可选一层 1px `rgba(255,255,255,.06)` 的 SVG 椭圆，旋转 -24°，增强“星系盘”的实体感。
- **范围**：以上全部为 Canvas 2D 实现。WebGL 仅作为 v2 的性能备选，不计入本期交付，也不作为降级层。

**流星**（同一 Canvas 2D 画布）：

- 每 7–12s 随机 1 颗，最多同时 2 颗。
- 起点：`left 55%–95%`、`top 5%–40%`；方向 -28°；位移 320–480px；时长 700ms。
- 拖尾 120px，用 `createLinearGradient` 画 `rgba(255,255,255,.9) → transparent` 的 2px 线段；头部 2px 圆点。渐变对象按流星创建一次，不逐帧新建。
- 透明度 0 → 0.9 → 0；`ease-out`。
- `prefers-reduced-motion` / `document.hidden` 时不生成。

### 4.8 降级方案

按优先级逐级回退，任何一级都必须完整可用：

1. **`prefers-reduced-motion: reduce`**
   - 星系静止（渲染一帧后停止 rAF）；
   - 流星不生成；星点不闪烁；
   - 搜索/抽屉过渡 1ms；
   - 所有信息与交互不变。
2. **Canvas 2D 不可用**（`getContext('2d')` 返回 null / CSP 阻止 / 极旧内核）
   - 星点：3 层 CSS `radial-gradient` 重复背景（1px/1.5px/2px，透明度 .35/.55/.8）；
   - 星系：一张内联 SVG 静态旋涡（3 条弧线 + 中心圆），透明度 .55，不旋转；
   - 背景：静态深空渐变 + 2 个星云径向渐变；流星不生成；搜索与抽屉照常。
3. **`backdrop-filter` 不支持**
   - 搜索框/抽屉（以及 v1.5 的结果面板）改用 `rgba(11,18,32,.88)` 实色；边框与高光保留。
4. **低性能设备**
   - 粒子 1600 → 900；
   - DPR 上限 `min(devicePixelRatio, 1.5)`；
   - 帧率上限 30fps（每两帧更新一次旋转角，复用上一帧的 cos/sin）；
   - 移动端流星最多 1 颗。

### 4.9 性能预算

| 指标 | 目标 | 做法 |
|---|---|---|
| 首屏可输入 | ≤ 1.5s（本地） | 搜索框是普通 DOM，先渲染；星系在 `requestIdleCallback`（超时 500ms）后初始化 |
| 帧耗时 | ≤ 4ms/帧（中端笔记本） | 1600 点、单画布一次合成、无逐帧分配；每帧只算一次旋转角与全局 cos/sin |
| 帧率 | 60fps；移动端允许 30fps | `requestAnimationFrame` + 帧率上限；不在 rAF 内读布局 |
| CPU | 平均 < 5% | 页面隐藏时暂停；`document.hidden` 监听；无 React 每帧 setState |
| 内存 | < 30MB 增量 | Float32Array 预分配 + 3 张 sprite；无每帧对象创建 |
| 玻璃 | 最多 3 个 `backdrop-filter` 元素 | 搜索框、抽屉（v1.5 再加结果面板）；星点不用 blur |
| 首屏资源 | 0 个新增第三方库 | 原生 Canvas 2D；无 WebGL、three.js、GSAP 或粒子库 |

**不阻塞输入**：canvas 初始化放在首帧之后；搜索框在 React 水合前就是可聚焦的 `<input>`；不在 `input` 事件里做粒子计算。

**与调研的取舍**：调研建议 tsParticles slim（~25 KB）或 Canvas 2D。ADR-018 定为**零依赖 Canvas 2D 单画布**，既精确控制旋臂、倾角与流星节奏，又不新增依赖、不引入 WebGL 上下文；性能护栏与降级链按此设计。WebGL 仅作为 v2 备选，不算本期交付。

## 5. 设计原则摘要（一页）

| # | 原则 | 做法 | 反例 |
|---|---|---|---|
| 1 | 先层级，后装饰 | 每屏先定“主任务 / 次任务 / 辅助信息”，再选颜色与动效 | 首页堆数据卡片，搜索框被星系淹没 |
| 2 | 一屏一个主任务 | 新建弹窗只做“创建”；管理、筛选、统计都退到次级入口 | 弹窗里塞入完整词表编辑器 |
| 3 | 分类是结构，标签是属性 | 分类单选 chip、标签多选 chip，输入框只用于过滤；选中图形不同 | 分类也做成自由输入，筛选与流转语义崩坏 |
| 4 | 词表只有一份真相 | 所有入口读写同一套表；改完即刷新，计数同源 | 弹窗里缓存在 useState，管理页改完不生效 |
| 5 | 主题是 token 映射 | 组件只用语义变量；换肤只换变量表 | 组件里写死 `#fff`，深色主题出现白块 |
| 6 | 默认主题零变化 | 松林绿所有值原样保留；新主题是加法 | 借改版“顺手优化”默认绿，用户认不出原界面 |
| 7 | 深色不用纯黑，强调不过量 | 最暗 `#070b14`；强调色面积 ≤10% | 大面积霓虹青，阅读疲劳 |
| 8 | 玻璃只用于悬浮层 | 搜索、抽屉、弹窗遮罩；内容卡片实底 | 每张卡片都毛玻璃，层级全部糊在一起 |
| 9 | 动效服务定位与反馈 | 160–240ms；只做位移/透明度；超 300ms 必须有理由 | logo 持续旋转、列表逐项飞入 |
| 10 | 降级不是可选项 | reduced-motion / 无 Canvas 2D / 无 backdrop-filter 都要完整可用 | 动画失败后首页一片黑 |
| 11 | 空状态是引导 | 说明为什么空 + 下一步按钮 + 示例 | 只显示“暂无数据” |
| 12 | 窄屏先删后藏 | 先减装饰，再藏次要信息，最后才横向滚动 | 为了保留桌面布局，390px 出现横向滚动条 |

**一句话**：这次改版不是把界面“做得更花”，而是把**结构（分类）**、**属性（标签）**、**身份（主题）**、**入口（首页）**四件事分别放在正确的层级上；银河只是首页的背景，不是每个页面的滤镜。

### 6.1 分类选择器 CategoryPicker / 标签选择器 TagField

一句话：**ADR-023 定的两个组件、一套骨架**。`CategoryPicker`（单选）与 `TagField`（多选）共用内部的候选区、chip、折叠、状态与键盘规则；除选择图形与计数文案外，尺寸与行为完全一致。对外不暴露统一的 `mode` prop，避免「一个组件两种语义」在调用处失控。

#### 6.1.1 结构（≥ 560px）

```
┌ 分类   单选 · 从全站词表选择                        已选 1   ⚙ 管理 ┐
│ ┌──────────────────────────────────────────────┐ ┌────────────┐  │
│ │ [✓ 文章]    [课程]      [直播]                │ │ ＋ 自定义  │  │
│ │ [咨询]      [外部笔记]  [音视频脚本]          │ │    分类    │  │
│ │ 展开全部 7 个 ▾                               │ └────────────┘  │
│ └──────────────────────────────────────────────┘                  │
│ 分类决定内容归到哪一类；改名、排序、停用在「管理分类」完成。       │
└────────────────────────────────────────────────────────────────────┘

#### 6.1.2 候选区呈现规则

1. **排序**：严格按 `sortOrder` 升序，与词表管理页一致（ADR-023 §8）。`usage` 只在管理页展示，不参与排序。**不做「已选置顶」**：点选后位置不跳动，每次打开顺序一致。
2. **折叠**：默认只显示 2 行（分类 3 列 × 2 = 6 个，标签约 12 个）。超出时底部出现「展开全部 N 个 ▾」；展开后候选区 `max-height:240px`、内部滚动，按钮改为「收起 ▴」。展开状态不持久化。
3. **面板内搜索**：候选 > 12 个时，候选区顶部粘一条搜索框（14 图标 + 13 文字，placeholder「筛选分类」/「筛选标签」），按 `normalized` 包含匹配，输入即筛，无需回车；搜索态下不折叠。
4. **过滤无匹配**：候选区显示一行 13/`--text-3`「没有这个分类，点右侧『自定义』新建」（标签同理），右侧 12「＋ 新建「xxx」」文字按钮，带当前输入打开自定义弹窗。
5. **空词表**：候选区高 92，居中两行——14 图标 + 13/`--text-3`「还没有分类」/「还没有标签」；下方一行 12/`--text-2`「先新增一个，之后所有内容都能选到它」。有 `object:write` 可直接点右侧「＋ 自定义」；只读用户文案改「请联系管理员添加分类」。
6. **达到上限（标签 10 个）**：未选项 `aria-disabled="true"`、透明度 .45、`cursor:not-allowed`，仍可聚焦，激活时用 live region 播报「最多选择 10 个标签」；计数变 `10/10`、`--text-2`、600。
7. **长名称**：chip 单行、`text-overflow:ellipsis`、`title` 与 `aria-label` 给全称；不使用两行（两行会让 2 行折叠的高度不可预测）。
8. **停用项**：停用分类不出现在候选；已选中的停用分类以只读 chip 显示（`--surface-2` 底、`--text-3`、无勾、右上角 10「已停用」角标），只能被替换。
9. **新增成功后**：新 chip 插到词表顺序的末尾并选中，滚动到可见，聚焦它；600ms `--accent` 外环提示，随后回到常规选中态。

#### 6.1.4 键盘与读屏

- 整块是一个组合：`role="group"` + `aria-labelledby` 指向标题；候选列表 `role="listbox"`，分类 `aria-multiselectable="false"`，标签 `="true"`；每项 `role="option"` + `aria-selected`。
- **Tab 顺序**：管理链接 → 面板内搜索（若有）→ 候选列表（**只占 1 个 Tab 位**）→ 自定义按钮 → 下一个字段。列表内部用 roving tabindex，不产生 N 个 Tab 位。
- 列表内：`←/→/↑/↓` 按 DOM 顺序移动（不按视觉网格跳格，避免换行后不可预测）；`Home/End` 到首/末；`Space` 或 `Enter` 切换（分类即选中）；`Esc` 在面板搜索里先清空筛选，再按一次焦点回列表；弹窗的 Esc 关闭不受影响。
- 读屏标签：列表 `aria-label="分类，单选，共 7 个，已选 1 个"`；每项 `aria-label="文章，已选中"`（未选则「文章」）；计数容器 `aria-live="polite"`，只在选择变化时播报「已选 2 个标签，上限 10 个」，不做逐键播报。
- 自定义按钮：`aria-haspopup="dialog"`；弹窗关闭后焦点回到该按钮。
- 错误与空态用 `role="status"`；加载用 `aria-busy="true"`。

### 6.4 首页搜索框与快速结果（ADR-024 定稿）

现状：首页只做「回车跳 `/search`」（§4.6 v1）；本期升级为**输入即出预览**，只查词法层，不碰 RAGFlow。正文关键词由 `/search` 页的语义层承担，这个边界必须写进界面文案。

#### 6.4.1 触发与请求

| 项 | 规则 |
|---|---|
| 最小输入 | **归一化后 ≥ 2 个字符**（NFKC、小写、空白压缩后计数）。中文单字不发请求：`知` 不发，`知识` 发 |
| 防抖 | **200ms**；`compositionstart`–`compositionend` 期间不请求，结束后重新计时 |
| 请求 | `GET /api/search?mode=lexical&limit=8&q=<原文>`；**只走词法，不调 RAGFlow**，保证输入不掉帧 |
| 取消 | 每次输入 `AbortController` 取消上一轮；按请求序号丢弃过期响应 |
| 结果数 | 取 `lexical.total`；`truncated = true` 时页脚改「结果过多，请加关键词」 |
| 回车 | 有高亮行 → 打开该对象；无高亮行 → `/search?q=`（完整混合检索） |
| 失败 | 面板 96 高错误行 + 重试；输入保留 |
| 语法错误 | 服务端 400 `QUERY_SYNTAX`：面板不展开，输入框下方提示 + 位置；不重发请求 |
| 上限 | `q` ≤ 200 字；超出前端直接拦截，不再敲网络 |

#### 6.4.2 搜索框状态

| 状态 | 表现 |

#### 6.4.4 检索语法（ADR-024 第 3 条）

| 语法 | 含义 | 例 |
|---|---|---|
| 空格 | 全部命中（隐式 AND） | `写作 复盘` |
| `"短语"` | 精确短语，整段子串匹配 | `"个人知识系统"` |
| `title:` / `标题:` | 只匹配标题 | `title:复盘` |
| `desc:` / `描述:` | 只匹配描述 | `desc:模板` |
| `category:` / `分类:` | 只匹配分类名 | `分类:课程` |
| `tag:` / `标签:` | 只匹配标签名 | `标签:工具类` |
| `-词` | 排除：任一字段命中即排除 | `复盘 -草稿` |
| `AND` | 与空格等价，兼容旧习惯 | `写作 AND 复盘` |
| `NOT` | 与 `-` 等价 | `NOT 草稿` |
| `OR`、括号 | **不支持**：400 `QUERY_SYNTAX`，给可操作提示与位置 | `写作 OR 复盘` |
| `~` | **不支持**：按普通字符参与匹配，结果页给一次提示 | `复盘~` |
| 未知 `x:` | 当普通文本（避免把 `http://` 误判为字段） | `http://…` |

- **错误清单**：未闭合引号、只有 `-`、`OR`、括号、`q` 超 200 字 → 400 `QUERY_SYNTAX`，`details.position` 给出错位置；前端据此画波浪线并显示修正建议，**不发第二次请求**。
- 位置约定：服务端 `details.position` 为 0 基下标，界面显示「第 position+1 个字符附近」。
- 少于 2 个字符（归一化后）→ 服务端 200 + 空结果 + `hint: "至少输入 2 个字"`；首页预览直接不发请求。
- 错误提示文案：
  - `OR`：「不支持 OR。分两次搜索，或改用标签筛选。」
  - 括号：「不支持括号组合。用空格表示同时满足，用 `-` 表示排除。」
  - 未闭合引号：「引号没有闭合，请在短语末尾补一个 `"`。」
  - 只有 `-`：「`-` 后面要跟一个词。」
- `~` 的处理：不报错，按普通字符参与匹配；`/search` 页在结果上方给一次 12 的提示「关键词匹配默认就是模糊匹配，不需要 ~」，同一会话只出现一次。
- 解析、归一化、评分放在 `src/lib/search-query.ts`（ADR-024 命名），下拉与 `/search` 共用同一份；查询串先经 `normalizeSearchText()` 再进 SQL。

## 附录 A：数据与接口约定（现行实现 = ADR-016；目标态见 ADR-023）

> **本附录描述迁移前的现行实现**（截至 2026-11-12，ADR-016 已落地）。ADR-023（已采纳、待实施）会把 `work_formats` 改名为 `categories`、`objects.format` 改为 `objects.category_code`、路由与权限键同步改名，并删除 `objects.categories` / `primary_category`。**以本节为现状依据、以 §6.0.1 与 ADR-023 为实施目标**；两者冲突时按 ADR-023。**例外：A.3 接口表已按 ADR-023 更新为现行分类接口**（见该节说明），其余小节仍描述迁移前状态。

### A.1 现状与已落地部分

- **ADR-016 已落地**：`work_formats`、`tags`、`object_tags` 已在 `src/server/db/schema.ts` 定义；`objects.format` 改为指向 `work_formats.code` 的外键，原六值 CHECK 已移除。
- `objects` 表已不再保存标签；标签关系只存在于 `object_tags`（`object_id` + `tag_id` 联合主键），对象软删后关联保留，统计时排除。
- `/api/vocabulary` 接口与 `src/server/services/vocabulary-service.ts` 已实现：词表快照、分类增改停删/迁移、标签增改删/合并，标签使用数已显式排除软删对象。
- **剩余待做（本文负责其视觉与交互规格）**：`/admin/vocabulary/*` 两个管理页、第二列「管理」分组、弹窗内「＋ 自定义分类」入口。数据与接口不再是阻碍。

### A.2 表结构（对齐 ADR-016 / R1 / R2）

```sql
-- 分类词表（内部名 work_formats）：objects.format 存 code；code 是主键、创建后不可改 → 改名只动 label
CREATE TABLE work_formats (
  code        TEXT PRIMARY KEY,              -- article | script | course | live | consult | flomo | 自定义
  label       TEXT NOT NULL,                 -- 显示名，1–12 字
  sort_order  INTEGER NOT NULL DEFAULT 0,    -- 步长 10
  state       TEXT NOT NULL DEFAULT 'active' CHECK (state IN ('active', 'archived')),
  is_system   INTEGER NOT NULL DEFAULT 0,    -- 内置项不可删
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);

-- 标签主表：只存词条与显示名，不存使用次数；改名只改 label（O(1)）
CREATE TABLE tags (
  id          TEXT PRIMARY KEY,              -- ULID
  label       TEXT NOT NULL,                 -- 显示名，1–20 字，保留首次创建写法
  normalized  TEXT NOT NULL,                 -- NFKC + lower，全局唯一
  sort_order  INTEGER NOT NULL DEFAULT 0,
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
CREATE UNIQUE INDEX tags_normalized_uq ON tags(normalized);

-- 对象 ↔ 标签：真多对多；两侧级联，对象软删不触发级联
CREATE TABLE object_tags (
  object_id  TEXT NOT NULL REFERENCES objects(id) ON DELETE CASCADE,
  tag_id     TEXT NOT NULL REFERENCES tags(id)    ON DELETE CASCADE,
  PRIMARY KEY (object_id, tag_id)
);
CREATE INDEX object_tags_tag_idx ON object_tags(tag_id);
```

- `objects.format` 外键指向 `work_formats(code)`；应用层仍做启用态校验，两层都不省（R1）。
- **标签不存在于 `objects` 行内**：对象读写时通过 `object_tags` 组装 `tags: string[]` 返回，对外契约保持不变。
- 删除约束：内置分类不可删；自定义分类有引用时只能停用或迁移；至少保留 1 个启用分类。标签有引用时不能直接删，只能合并或显式「同时从 N 个对象移除」。
- 计数：任何 `usage` 查询都 `JOIN objects` 并加 `deleted_at IS NULL`（见 §2.4），软删对象不计入。

### A.3 接口（与现有实现一致）

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/vocabulary` | 词表快照：全部分类 + 标签 + 使用数（弹窗/筛选/详情共用） |
| POST | `/api/vocabulary/categories` | 新增分类（`object:write` 即可，内联创建；`reuseExisting` 命中启用项 → 200 复用，否则 409 `CATEGORY_EXISTS`） |
| PATCH | `/api/vocabulary/categories/:code` | 改名 / 排序 / 停用（需 `vocabulary:category:write`，code 不可改） |
| DELETE | `/api/vocabulary/categories/:code` | 删除；内置或带引用返回 409 + 使用数；`?migrateTo=<code>` 先迁移再删 |
| POST | `/api/vocabulary/tags` | 新建标签（`object:write` 即可，内联创建；`normalized` 命中则复用） |
| PATCH | `/api/vocabulary/tags/:id` | 改名（仅管理员；只改 label / normalized） |
| DELETE | `/api/vocabulary/tags/:id` | 删除；有引用返回 409；body `{ "removeFromObjects": true }` 才连同对象关联一起删 |
| POST | `/api/vocabulary/tags/:id/merge` | 合并到 `targetId` 或 `targetLabel`（仅管理员） |

- 页面路由与 API 前缀不同：管理页是 `/admin/vocabulary/categories|tags`（ADR-023；旧 `formats` 308），数据接口是 `/api/vocabulary/*`（已实现），两者不要混用。
- **ADR-023 已落地**：分类接口就是 `/api/vocabulary/categories` 与 `/api/vocabulary/categories/{code}`，词表响应键为 `categories[]`；旧 `/api/vocabulary/formats`、`/api/vocabulary/formats/{code}` 的 GET/POST/PATCH/PUT/DELETE **一律 308 跳转**到分类地址（保留方法与查询串），**不提供任何写入能力**，仅保留一个版本，新代码不要再用。
- 读取：所有登录用户；内联新增（分类 / 标签）：`object:write`；改名 / 排序 / 停用 / 删除 / 合并：对应的 `vocabulary:category:write`、`vocabulary:tag:write`。
- 缓存：`revalidateTag("taxonomy")` + `revalidatePath("/workspace")`、`("/search")`、`("/admin")`。
- 错误：409（被引用 / 重名）、422（重名/超长/空值）、403（无权限），前端按字段提示。
- 对外对象契约不变：`GET/POST/PATCH /api/objects` 的 `tags` 仍是 `string[]`，由服务层负责与 `object_tags` 互转。

### A.4 迁移顺序（ADR-016 已按此落地；ADR-023 的 `0007` 在此之上再迁一次）

> ADR-023 的迁移 SQL、验证查询与回滚步骤见 `docs/03_DECISIONS.md` ADR-023 第 4–5 条；本节保留 ADR-016 的历史顺序，不再重复。

1. 建 `work_formats`、`tags`、`object_tags`，种子 6 个分类（code 与现存量一致）。
2. `objects.format` 从六值 CHECK 改为 `work_formats(code)` 外键；存量 6 类作品读写无损。
3. 回填历史标签：逐对象读取旧标签列 → NFKC 归一化去重 → upsert `tags` → 写 `object_tags`；校验关联数与对象数后**删除旧标签列**。此后对象表不再有标签字段。
4. 读路径切到词表快照（弹窗、筛选、详情、导出），不再引用编译期分类常量。
5. 上线管理页与目录入口（仅管理员），弹窗「＋ 自定义分类」调用同一服务。

- 表格：容器圆角 12px、1px `--line`、`--surface` 底；表头 36px、12/600 `--text-3`、`--surface-2` 底；行高 48px（对象表 52px）；行 hover `--surface-2`；分割线 `--line-soft`。
- 数字列右对齐、`font-variant-numeric: tabular-nums`；状态用徽标（启用绿 / 停用灰 / 内置蓝 / 失败红），不只靠颜色，带文字。
- 行尾操作最多 3 个文字按钮；更多操作收进「⋯」菜单，避免表格横向溢出。
- 筛选条高 44px：搜索 280px、下拉 160px、右侧「重置」；筛选条件写进 URL，刷新与前进后退不丢。
- 移动端（≤ 900）：表格改卡片列表，每张卡 2 行主信息 + 1 行元信息；批量操作固定在底部。

### E.4 危险操作与状态

- 确认弹窗 420px：标题 16/600、正文 13 写明「影响 N 个对象」与「是否可恢复」、危险按钮在右；删除类按钮 `--danger-fg` 底白字或红底白字，不用绿色。
- 角色页：只读矩阵用 ✓ / —，禁用态不显示可点击开关；页面顶部固定一条说明条「当前只有所有者角色实际生效」。
- 用户页：不出现邀请、删除、改角色按钮；「复制完整 sub」成功用 toast，不弹窗。
- 加载：表格骨架 6 行，行高一致；不用整页 spinner。
- 空状态：图标 32 + 一句解释 + 一个下一步按钮；例如审计页「还没有审计记录，词表与批量操作会记录在这里」。
- 错误：保留筛选与输入，表格上方 1 条 `--danger-bg` 提示 + 「重试」；不整页跳错。
