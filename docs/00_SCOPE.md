# 产品边界与最终决策（SCOPE）

> 本文件是项目方向锚点。重大变更必须同步更新 03_DECISIONS.md 并说明原因。

## 1. 项目目标（一句话）
构建一个以 **RAGFlow 为统一内容存储与检索底座**，在其上实现资产管理和四阶段工作流，并结合 LightRAG 提供知识图谱能力，通过 Logto 提供登录注册的个人知识工作台。

## 2. 核心定位变化（重要）

| 旧思路 | 新思路（当前） |
|--------|----------------|
| 以本地 Markdown 文件为唯一内容真相 | 以 RAGFlow 的存储与解析能力为统一内容底座 |
| 知识库是附加能力 | 知识库（RAGFlow）是内容管理的核心 |
| 资产/工作流直接操作文件系统 | 资产/工作流作为业务层，建立在 RAGFlow 内容之上 |

**统一原则**：所有需要被管理、检索、关联的内容，最终都进入 RAGFlow 进行存储与索引；业务侧（资产、工作流）维护元数据、状态与关系，而不是再维护一套独立的文件真相源。

## 3. 第一期明确范围

### 保留并重新定义的核心
- **作品**：完整生命周期 `draft → finished → published → practiced`，内容存储走 RAGFlow。**作品只存在于外库**，`practiced` 是终点（ADR-029 取代 ADR-008 的「先迁内库才能已实践」）
- **资产**：作为业务对象存在（内库/外库、分类、标签、优先级、来源类型、AI 评分、价值等级等元数据），其内容主体由 RAGFlow 管理。**内库只有资产**
- **内库入库只有两条路径**：外库资产的 AI 六维综合分 ≥ 75 自动入库，或 60–74 分经人工复核通过；跨库迁移接口不能把外库资产直接改到内库
- **四阶段工作流**：状态流转与业务规则保留，状态变化只改业务元数据，不移动内容

### 内容流转与沉淀规则（ADR-029）
- 所有外部资料与批量导入先进入外库；AI 自动提炼只能从外库作品的**草稿**触发，产物是外库资产，随后走六维打分
- 「已发布 → 已实践」由用户结合数据反馈手动确认（可填平台、浏览量、跳出率、反馈摘要），**同一请求内**自动创建内库资产（`source_type = practiced_work`，`origin_work_id` 指回作品）并立即完成 5 维价值评估、赋 S/A/B/C；不存在「已实践但未沉淀」的中间状态
- 内库资产必须带 5 维评分（1–5 分）与等级，由数据库 CHECK 兜底；模型不可用时用确定性兜底并标注评估来源（`value_scores.source = fallback`），不得跳过评估
- 动态调整（调用次数、长期未调用、新实践数据触发重新分级）列为后续迭代，字段先落库

### 明确砍掉（第一期不做）
- 以本地 Markdown 文件为唯一真相的旧存储模式
- 旧知识图谱实现
- 加密分享（AES ZIP）
- 平台试运行评估（旧系统的「试运行」AI 评估，与 ADR-029 的资产打分 / 价值评估不是同一功能）
- 多用户数据隔离
- 复杂命令面板与高级批量能力（可后续加）

### 新增
- Logto 自托管登录/注册（第一期仅身份，不做权限隔离）
- RAGFlow 本地 Docker：承担**统一内容存储、解析、分块、向量化与检索**
- LightRAG：提供知识图谱能力（与 RAGFlow 共用 Embedding，独立向量/图存储）

## 4. 关键约束
- 旧系统无数据，无需迁移
- 第一期单用户
- 内容统一由 RAGFlow 管理，不再把本地文件系统当作内容真相源
- LightRAG 与 RAGFlow：共用 Embedding 模型，不共用向量库（见 ADR-001）
- 技术栈：**待从零搭建**的 Next.js 前端/API + 本地 Docker 服务（Logto、RAGFlow）+ LightRAG

### Greenfield 起点

ADR-006 确认时，本仓库全部内容为：

### 当前新增实现

- 已按 ADR-006 从零创建 Next.js App Router + TypeScript 骨架，新增业务 `src/` 与 `package.json`；这不是对旧前端的改造
- 当前仅有本地 UI / 健康检查 / 元数据 DRAFT，真实 Logto、RAGFlow 与业务 CRUD 尚未接入
- 资产 / 四阶段等工作流规则仍来自产品决策与文档，**实现时需新写**
- Phase 1 剩余重点是将 Mock 身份替换为真实 Logto 登录 / 注册 / 会话，而非重复初始化应用

## 6. 成功标准（第一期结束时）
- 用户可通过 Logto 登录
- 内容可进入 RAGFlow 并完成解析与检索
- 资产与四阶段工作流可基于 RAGFlow 中的内容正常运转
- 作品可走完「发布 → 已实践」，并在同一次操作里沉淀出带 S/A/B/C 等级的内库资产；AI 提炼与资产复核可用
- LightRAG 可对内容构建与查询知识图谱
- 文档体系（本目录）保持更新，方向未跑偏
- 业务应用代码（Next.js 等）已在本仓库中落地并与文档一致
