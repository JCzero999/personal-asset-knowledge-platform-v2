# 产品边界与最终决策（SCOPE）

> 本文件是项目方向锚点。重大变更必须同步更新 03_DECISIONS.md 并说明原因。

## 1. 项目目标（一句话）
构建一个以 **RAGFlow 为统一内容存储与检索底座**，在其上实现资产管理和四阶段工作流，并结合 LightRAG 提供知识图谱能力，通过 Logto 提供登录注册的个人知识工作台。

## 2. 核心定位变化（重要）

| 旧思路 | 新思路（当前） |
|--------|----------------|
| 以本地 Markdown 文件为唯一内容真相 | 以 RAGFlow 的存储与解析能力为统一内容底座 |
| 知识库是附加能力 | 知识库（RAGFlow）是内容管理的核心 |
| 资产/工作流直接操作文件系统 | 资产/工作流作为业务层，建立在 RAGFlow 内容之上 |

**统一原则**：所有需要被管理、检索、关联的内容，最终都进入 RAGFlow 进行存储与索引；业务侧（资产、工作流）维护元数据、状态与关系，而不是再维护一套独立的文件真相源。

## 3. 第一期明确范围

### 保留并重新定义的核心
- **资产**：作为业务对象存在（内库/外库、分类、标签、优先级等元数据），其内容主体由 RAGFlow 管理
- **四阶段工作流**：draft → finished → published → practiced，状态流转与业务规则保留，内容存储走 RAGFlow

### 明确砍掉（第一期不做）
- 以本地 Markdown 文件为唯一真相的旧存储模式
- 旧知识图谱实现
- 加密分享（AES ZIP）
- 平台试运行评估（AI 评估）
- 多用户数据隔离
- 复杂命令面板与高级批量能力（可后续加）

### 新增
- Logto 自托管登录/注册（第一期仅身份，不做权限隔离）
- RAGFlow 本地 Docker：承担**统一内容存储、解析、分块、向量化与检索**
- LightRAG：提供知识图谱能力（与 RAGFlow 共用 Embedding，独立向量/图存储）

## 4. 关键约束
- 旧系统无数据，无需迁移
- 第一期单用户
- 内容统一由 RAGFlow 管理，不再把本地文件系统当作内容真相源
- LightRAG 与 RAGFlow：共用 Embedding 模型，不共用向量库（见 ADR-001）
- 技术栈：**待从零搭建**的 Next.js 前端/API + 本地 Docker 服务（Logto、RAGFlow）+ LightRAG

## 6. 成功标准（第一期结束时）
- 用户可通过 Logto 登录
- 内容可进入 RAGFlow 并完成解析与检索
- 资产与四阶段工作流可基于 RAGFlow 中的内容正常运转
- LightRAG 可对内容构建与查询知识图谱
- 文档体系（本目录）保持更新，方向未跑偏
- 业务应用代码（Next.js 等）已在本仓库中落地并与文档一致
