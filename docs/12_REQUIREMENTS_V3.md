## R1　作品形态可自定义（P0）

### 目标

让「形态」从代码常量变成可维护的业务词表；用户新增一个形态后，全站立刻可用，不需要改代码、不需要重启。

### 用户故事

- 作为内容作者，我想新增「播客」这类我实际在做的形态，**以便**新建作品时能直接选中，而不是被迫归到「文章」。
- 作为内容作者，我想把「音视频脚本」改名成「短视频脚本」，**以便**词表跟上我的说法，同时不破坏已有作品的归属。
- 作为内容作者，我想停用一个不再做的形态，**以便**新建时不被无关选项干扰，但旧作品仍显示原来的分类。

### 方案要点（对齐 ADR-016 第 1、2、7 条）

1. **数据模型**：`work_formats(code PK, label, sort_order, state, is_system, created_at, updated_at)`，`state ∈ {active, archived}`。`objects.format` 保留列名与类型，只把 `objects_format_check` 换成 `FOREIGN KEY (format) REFERENCES work_formats(code)`。
2. **改名与数据分离**：`code` 一经创建不可改，改名只改 `label`；存量 6 个 code 天然就是合法外键值，**不需要重写任何一行业务数据**。
3. **删除 / 停用规则**：
   - 内置形态（`is_system = 1`，含系统兜底 `uncategorized`「未分类」）：不可删除，只能改名、排序；「未分类」还不可停用。
   - 自定义形态且**无引用**：可直接删除。
   - 自定义形态且**有引用**：删除被拒绝（409，`details` 带 `usage` 与前 5 个对象），界面给两个出口——**停用**，或**迁移到…**（目标默认「未分类」，也可选其它启用形态；单事务改完再删）。
   - 停用后：新建面板不出现，历史对象照常显示原 label + 「已停用」标记，管理页可恢复。
4. **不允许为空**：作品必须有形态，新建时默认选中排序第一的启用形态。
5. **不会出现「无可选形态」**：`uncategorized` 是系统项且不可停用，天然兜底。

> **第 5 版修订**：本节的「形态」对外统一称「分类」（ADR-023），选择方式**维持单选**，只是候选来自合并后的 `categories` 词表、控件由 chip 换成受控选择器；`format` 列退场，改由 `category_code` 承载。其余规则（`code` 稳定、停用 / 迁移、兜底、上限 30）继续有效，详见 R7.2 / R7.6。

### 功能点

| 位置 | 行为 |
|------|------|
| 形态管理页（`/admin/vocabulary/formats`） | 列表：名称、code、作品数、状态（启用/停用/内置）、排序；操作：新增、改名、上移/下移、停用/启用、删除（受引用保护）、迁移 |
| 新建作品弹窗 | 形态 chips 从词表读取，按 sort_order 排列，只显示 `active` 项 |
| 编辑作品弹窗 | 同上；当前形态已停用时仍显示为选中并标注「已停用」，允许原样保存 |
| 对象详情 | 展示 label；停用形态追加徽标 |
| 列表筛选 | **本轮不新增**分类筛选：`ObjectFilters` 现只有关键字 / 类型 / 库别 / 状态 / 标签 / 排序，ADR-023 明确不扩这个范围；检索页用 `分类:` 语法替代。若将来要做，另开 ADR |
| 导出 Markdown | 元信息写 label，不写 code |
| API 校验 | `format` 校验从常量改为查词表且 `state = 'active'`；错误码由 `VALIDATION_FAILED` 细化为 `NOT_FOUND` |

### 边界条件

- 名称 1–12 字；归一化后唯一；不能为空白或纯符号。
- 启用形态上限 30 个，超出拒绝并提示（新建面板要一次显示完，不做分页）。
- `sort_order` 用整数步长 10；v1 只做上移/下移，不做拖拽。
- 停用项在管理页排在启用项之后。
- 并发改名以 `updatedAt` 做乐观校验，冲突提示「已被修改，请刷新后重试」。

### 验收标准

1. 新建形态「播客」→ 新建作品选中它 → 刷新/重新登录后仍在；详情、列表、导出处显示同一个 label。
2. 把「文章」改名为「长文」→ 所有 `category_code = article` 的作品展示名变为「长文」；查库确认 `category_code` 仍为 `article`。
3. 停用「直播」→ 新建面板不出现；已有直播作品显示「直播（已停用）」。
4. 删除被 3 个作品使用的形态 → 409 且 `usage = 3`；「迁移到未分类」后 3 个作品变为 `uncategorized`，该形态可删。
5. `grep -rn "workFormats" src/` 除 `SYSTEM_FORMAT_SEEDS` 定义与测试外为 0。
6. 资产分类可空可为 1 个：给资产提交 `category` 正常保存；提交已退场的 `format` 字段返回 400。

### 依赖与风险

- 依赖 R3 的管理入口（也可先直链，入口后补）。
- 风险：7 处硬编码若漏改，会出现「筛选里叫文章、详情里叫长文」；ADR-016 用 ESLint `no-restricted-imports` + 测试断言兜底，验收第 5 条正是为此。
- **已定（ADR 裁决 #7）**：`uncategorized` **不作为筛选项**，只在对象详情与列表中作为兜底值展示；本轮不新增分类筛选控件（ADR-023，见 R8 边界）。

## R2　新增「标签」区（P0）

### 目标

把「标签」从只能手输的字符串，升级为有词表、可管理、可筛选的内容属性维度；与形态形成「形态 = 来源/体裁大类、单选」与「标签 = 内容属性、多选」的双维度。

### 用户故事

- 作为内容作者，我想在新建作品时直接输入「工具类」，下次它能出现在建议里，**以便**同类内容被统一归类。
- 作为内容作者，我想把「工具类」改名为「工具」，**以便**词表不出现同义分裂，而不用逐条改内容。
- 作为内容作者，我想按标签筛选列表，**以便**把「感悟类」的内容一次性挑出来复盘。

### 结论：资产也允许打标签

**允许。** 理由：标签是内容属性，资产同样有；限制它要额外写规则、额外报错分支，却没有收益。位置：作品的标签区在「作品形态」正下方；资产没有形态区，标签区放在「放在哪里」之后、简介之前。

### 方案要点（对齐 ADR-016 第 3、4、7 条）

1. **真多对多**：`tags(id, label, normalized UNIQUE, sort_order, created_at, updated_at)` + `object_tags(object_id, tag_id, PRIMARY KEY(object_id, tag_id))`，两侧外键；`objects.tags` JSON 列在本次表重建中删除，JSON 不再持有任何标签。
2. **对外形状不变**：`BusinessObject.tags` 仍是 `string[]`（元素为 label），仓储读取时批量水合。UI、导出、筛选、既有测试的契约都不变。
3. **一致性由数据库保证**：重命名只改 `label`（`object_tags` 存 `tag_id`），**重命名 O(1)、全站立即生效**；合并是一条 `UPDATE object_tags SET tag_id = ?` 配 `OR IGNORE`；使用次数是一次 `GROUP BY`。这正是「一处改了处处要改」的结构性解法。
4. **删除语义**：被引用时删除返回 409 并带 `usage`，引导改用「合并到…」；无引用才可真删。删除词表项与「把标签从对象上摘掉」是两件事，后者在编辑弹窗里做。
5. **新建弹窗必须补标签区**（当前只有编辑弹窗有）。
6. **软删对象不清理 `object_tags`**：引用检查与使用次数统计一律 `join objects where objects.deleted_at is null`，否则删标签会被看不见的引用挡住。

### 归一化规则（全局唯一一份实现，顺序对齐 ADR-016）

| 步骤 | 处理 |
|------|------|
| 1 首尾空白 | `trim` |
| 2 全角/半角 | 全角转半角（NFKC），`ＴＯＯＬ` 与 `TOOL` 视为同一 |
| 3 内部空白 | 连续空白压成一个 |
| 4 Unicode | NFC 归一化（组合字符统一） |
| 5 英文大小写 | ASCII 小写后比较；展示保留首次创建时的写法 |
| 6 分隔符 | `,` `，` `、` 回车 均视为分隔（沿用现有 `splitList`） |
| 7 重复 | `normalized` 命中即复用已有 `tag_id`，不报错也不新建 |
| 8 长度与数量 | 单标签 ≤ 20 字；单对象 ≤ 10 个；词表软上限 500（超出只警告） |

> **已定（2026-11-12）**：单对象标签上限取 **10 个**（本节口径），ADR-016 已按此回改，代码常量 `MAX_TAGS_PER_OBJECT = 10` 一致。

### 功能点

| 位置 | 行为 |
|------|------|
| 新建作品/资产弹窗 | 「作品形态」下方新增「标签」块：输入（回车或逗号确认）、已有标签为可点选 chip、已选 chip 可删、显示「3/10」计数、输入即按 `normalized` 命中则直接选中 |
| 编辑弹窗 | 复用同一组件；现有「逗号分隔文本框」废弃 |
| 对象详情 | 保留标签展示；点击标签跳到该标签的筛选列表 |
| 列表工具栏 | 新增「标签」下拉：选项 = 词表启用项 + 当前结果出现的标签，按使用数排序；可清除；与其它筛选叠加 |
| 标签管理页（`/admin/vocabulary/tags`） | 列表：名称、使用数、最近使用、状态；操作：改名、合并到…、删除、清理 0 引用 |
| 空状态 | 「还没有标签。在新建或编辑内容时输入即可自动出现。」 |

> **第 4 版修订**：新增标签不再在输入框内直接创建（原「输入即建词条」作废），改为「只能选已有 + 右侧『自定义』弹窗创建」；本表其它规则（多选、去重、上限 10、展示）不变，控件规格见 R7.3/R7.4。

### 边界条件

- 改名不动 `object_tags`，确认框只说明「全站显示名将变化」，不报影响数量（没有写入）。
- 合并需显示受影响对象数与目标标签使用数；主键冲突用 `OR IGNORE` 吞掉重复项，不静默丢标签。
- 删除被引用标签 → 409 + `usage`；无引用才可真删。
- 使用次数 = `count(distinct object_id)`，且只统计未软删对象。
- 读路径由 1 次查询变 2 次：列表页一次 `WHERE object_id IN (...)` 取关联再内存分组，禁止 N+1。
- 标签不允许层级、颜色、别名（v2 再议）。

### 验收标准

1. 新建作品在「标签」区点「自定义」新增「工具类」并选中，保存 → 详情显示该标签；再次打开新建弹窗，「工具类」出现在建议列表。（第 4 版修订：不再支持在输入框内输入即建，见 R7；原「输入后保存自动建词条」作废。）
2. 把「工具类」改名为「工具」→ 详情、列表、导出、筛选四处同时变为「工具」，无需任何额外写入或刷新缓存。
3. 依次输入「工具类」「 工具类 」「ＴＯＯＬ类」等归一化后重复的形式，词表不产生重复记录。
4. 在列表工具栏选中「感悟类」→ 仅显示含该标签的对象，URL 带 `tag=`，刷新与前进后退一致。
5. 合并标签 A → B：原含 A 的对象都含 B；同时含 A、B 的对象不重复；A 从建议列表消失。
6. 删除一个被软删对象「独占」的标签：软删对象不计入 `usage`，删除成功且不报外键错误。
7. 资产新建/编辑也能打标签并保存成功。

### 依赖与风险

- 依赖 R1 的弹窗改造（同一文件，建议合并一个 PR）。
- **风险 1：迁移要重建 `objects` 表**。`PRAGMA foreign_keys = OFF` 在 Drizzle 事务内无效，`DROP TABLE objects` 会被 `library_events` 外键挡住（ADR-016 已实测）；必须把外键开关移到 `migrate()` 外层并加 `foreign_key_check` 断言，先在 `data/app.db` 副本上演练。
- **风险 2：软删对象不清 `object_tags`**。外键级联不触发，统计与删除检查必须显式排除已删对象，否则计数虚高、删除被拒。
- **风险 3：测试基线**。22 文件 / 231 项里有 format / tags fixture，改仓储内部后需全绿；新增词表测试 ≥ 6 项。
- **实现约束（ADR-016）**：归一化只有一处服务端实现（写入 `normalized` 唯一列），前端用同一规则本地查重并提示「已有同名标签」；`usage` 统计必须 `join objects where deleted_at is null`，写进测试。

## R3　左侧目录新增「管理」区（P0）

### 目标

让词表维护有稳定入口，且**所有页面共用同一份数据**——不存在「这里改了、那里没变」。

### 用户故事

- 作为管理员，我想从目录直接进入形态与标签管理，**以便**不用记 URL。
- 作为管理员，我改完一个形态名称后，**希望**新建弹窗、筛选、详情、导出全都立刻一致。

### 功能点

| 项 | 规则 |
|----|------|
| 位置 | 第二列目录内新增分组「管理」，两项：「分类管理」→ `/admin/vocabulary/formats`（R8 P1 起改为 `/admin/vocabulary/categories` 并 308 旧地址）、「标签管理」→ `/admin/vocabulary/tags`（导航栏不加第二个入口） |
| 出现范围 | 工作台、检索、图谱、管理四个页面的第二列都显示（同一组件渲染、指向同一路由）；仅拥有 `vocabulary:category:write` / `vocabulary:tag:write` 的账号可见（v1 即 owner / admin），其余账号整组不渲染 |
| 权限 | 仅管理员可增删改；非管理员看不到入口，直链访问复用现有 403 说明页 |
| 唯一真相 | 读取一律走词表接口（`GET /api/vocabulary`），前端不持有形态/标签常量；写入只有一条路径（同一服务） |
| 生效方式 | 页面无本地副本，保存后不需要用户手动刷新缓存；服务端组件按请求读取 |
| 空状态 | 形态：「没有自定义形态，内置形态仍可改名或停用」；标签：「还没有标签……」 |
| 错误 | 保存失败保留输入 + 行内错误；词表接口不可用时，新建面板用 `SYSTEM_FORMAT_SEEDS` 兜底并提示「词表读取失败，使用默认形态」 |

### 边界条件

- 前端不得 `import` 形态常量作为默认值（ADR-016 用 ESLint 禁止）。
- 不提供「重建缓存」按钮：保存即生效，避免用户学会手动刷新。
- 目录里的计数不做轮询。

### 验收标准

1. 管理员在工作台目录看到「管理 → 分类管理 / 标签管理」；普通账号完全看不到。
2. 形态改名保存后，**不重启服务**，新建弹窗、列表筛选、对象详情在刷新后均显示新名称。
3. 删掉一个 0 引用标签，新建弹窗建议列表同步消失。
4. 提交空白名或超长名 → 行内报错，数据库无写入。
5. 非管理员直链访问词表管理页 → 403 说明页，无编辑控件。
6. 停掉词表接口后新建面板仍可用（默认形态兜底）并显示提示，不白屏。

### 依赖与风险

- 依赖 R4 的后台路由结构。
- 风险：前端若为性能缓存词表到模块级变量，就会出现「某页没变」；ADR-016 的单一读取入口 + 验收第 2 条是约束。

## R4　管理后台重构（P0 骨架 / P1 深化）

### 问题诊断

单页纵向堆叠三区块、无二级导航、无操作确认、无审计、无批量能力、账号归属表只能看且不解释用途。**简陋的根因是范围不清**，不是页面不够多。

### 务实的角色结论（必须先说清）

当前是 **Logto 单账号本地部署**。按 **ADR-019**，授权不再看环境变量：Logto 只证明「你是哪个 `sub`」，授权由本地 `users` / `roles` / `permissions` / `role_permissions` / `user_roles` 五张表承担。因此：

- **四种角色在接口层全部真实生效**（13 项权限 key），不存在「可点击却不起作用」的假开关。
- 但库里只有 **1 个真实账号**（本人 = 所有者），所以「改角色」「停用用户」在界面与接口上完整，**实际没有第二个用户可操作**——这是数据量事实，不是功能缺失。
- 多用户注册/邀请仍属 v2；`ADMIN_SUBS` 仅在「库中没有任何 active owner」时作为首次引导与逃生舱，**一旦存在 owner 就退出授权判断**。

### 角色模型与落地程度

| 角色 | 定义 | v1 落地程度 |
|------|------|-------------|
| 所有者 Owner | 拥有全部 13 项权限，含改他人角色、停用用户、引导绑定 | **实际生效**（首个登录者由 `ADMIN_SUBS` 引导写入 `users` 并授予 owner） |
| 管理员 Admin | 除 `user:write`、`role:write` 外的全部：内容、词表、运维、审计 | **实际生效**（矩阵 + 接口判定） |
| 编辑 Editor | 内容新增与修改（含归档），**不含删除、导出与词表管理** | **实际生效** |
| 只读 Viewer | 只能查看与检索 | **实际生效** |

### 权限矩阵

| 能力 | 所有者 | 管理员 | 编辑 | 只读 |
|------|--------|--------|------|------|
| 查看/检索内容 | ✅ | ✅ | ✅ | ✅ |
| 新建/编辑/归档内容 | ✅ | ✅ | ✅ | ❌ |
| 删除内容（软删） | ✅（二次确认） | ✅（二次确认） | ❌ | ❌ |
| 导出 Markdown | ✅ | ✅ | ❌ | ❌ |
| 批量归档/导出/删除 | ✅ | ✅ | ❌ | ❌ |
| 管理形态词表 | ✅ | ✅ | ❌ | ❌ |
| 管理标签词表 | ✅ | ✅ | ❌ | ❌ |
| 访问后台 | ✅ | ✅ | ❌ | ❌ |
| 系统运维（同步/解析） | ✅ | ✅ | ❌ | ❌ |
| 查看审计日志 | ✅ | ✅ | ❌ | ❌ |
| 修改他人角色 / 停用用户 | ✅（`/admin/users`，最后一个 owner 受保护） | ❌ | ❌ | ❌ |

> v1 执行口径：13 项权限在 `/api/**` 层由 `requirePermission` 判定（唯一强制层），UI 显隐只作体验、不是安全边界。批量条是否出现 = 所包含动作所需权限的交集（缺 `object:delete` / `object:export` 时整条不出现）。`/admin/roles` 只展示矩阵，v1 不开放角色编辑。

### 信息架构

| 分组 | 页面 | 展示 | 操作 |
|------|------|------|------|
| 总览 | `/admin` | 对象总数/作品/资产、解析待完成、同步失败、依赖服务、最近 5 条失败 | 刷新；快捷跳转 |
| 内容 | `/admin/objects` | 全量对象表：标题、类型、形态、标签、库别、状态、归属、更新时间；默认排除软删 | 筛选、跳详情、批量归档/导出/删除（二次确认） |
| 词表 | `/admin/vocabulary/formats` | R1 | R1 |
| 词表 | `/admin/vocabulary/tags` | R2 | R2 |
| 账号 | `/admin/users` | 来自 `users` 表：显示名、sub（截断）、邮箱、角色、状态、对象数、最近登录 | 分配/撤销角色、停用/恢复用户；无删除、无邀请；移除或停用最后一个 owner → 422 `LAST_OWNER` |
| 账号 | `/admin/roles` | 4 个系统角色 × 13 项权限矩阵，**只读**（`role:write` 已预留，v1 不开放自定义角色） | 无 |
| 系统 | `/admin/system` | 迁入现有依赖服务、存储与队列、账号归属 | 立即同步、推进解析（保留现有） |
| 系统 | `/admin/audit` | 审计日志：时间、操作人、动作、目标、结果 | 按动作/时间筛选（P1） |

二级目录按上表分组渲染，与工作台目录同组件同视觉。视觉与密度以 `13_DESIGN_V3.md` 附录 E 为准（页头 56px、行高 48/52、危险操作 420px 确认框等）。

### 通用交互要求

- **危险操作二次确认**：删除词表项、删除内容、批量迁移、批量归档——确认框必须写明**影响数量**与**是否可恢复**。
- **空状态**：每页都有具体文案与下一步动作。
- **错误**：保留现场，给可重试按钮，不整页跳错。
- **加载**：表格骨架 6 行，不用整页 spinner。
- **可访问性**：表头关联、确认框焦点锁定与 Esc 取消、状态不只靠颜色。

### 审计留痕（P1 起步）

必须记录：词表新增/改名/合并/删除（含迁移到未分类）、对象删除（单条与批量）、对象归档、库别迁移、导出、手动同步/解析、用户与角色变更、引导性绑定、以及 `result='denied'` 的 403 拒绝。字段：`id`、`actorSub`、`actorUserId`、`action`、`targetType`、`targetId`、`detail(JSON)`、`result ∈ {ok,error,denied}`、`createdAt`。

落库方式已由 **ADR-019 第 8 条**定：新表 `audit_events`，**与业务写在同一事务**，审计失败则业务回滚；唯一例外是 403 拒绝记录（无业务写可回滚，由 guard 独立写入，失败只记应用日志、绝不放行请求）。`library_events` 保留为领域记录，库别迁移同时写一条审计。

### 参考实现

调研结论见 [14_REFERENCE_RESEARCH.md](14_REFERENCE_RESEARCH.md)：UI 借鉴 shadcn 的布局与表格质感，**不引入 Tailwind**。CASL 已由 **ADR-019 第 11 条否决**（13 权限 × 4 角色是二维常量表，`permissions.includes(key)` 足够），本文按该结论执行。

### 验收标准

1. 管理员从左侧目录能进入任意后台页；每页有独立 URL，刷新不丢筛选状态。
2. `/admin/users` 列出 `users` 表里的账号与角色；owner 能给第二个已登录账号分配 admin 角色，被分配者刷新后能进后台（当前只有 1 个账号时，以 `AUTH_MODE=mock` 造第二个账号验证）；页面无删除/邀请按钮。
3. `/admin/roles` 为只读表格，无任何可提交控件；4 个系统角色 × 13 项权限与 ADR-019 矩阵逐格一致。
4. 批量归档 5 个对象 → 确认框写明「5 个对象、可在已归档中恢复」→ 确认后列表与工作台计数同步变化。
5. 任一危险操作取消后，数据无任何变化；以 viewer 身份调 `DELETE /api/objects/{id}` 返回 403 且审计多一条 `result='denied'`。
6. 非管理员访问任一 `/admin/*` → 403 说明页。
7. 清空 `ADMIN_SUBS` 并重启（已有 owner）→ 仍能进后台，证明环境变量已不是授权源。

### 依赖与风险

- 依赖 **ADR-019** 的六张表与 `requirePermission`；依赖 R1、R2 的词表页；403 页已有。
- 风险：批量操作与现有状态机冲突（外库不能 practiced 等），批量迁移形态必须仍满足 CHECK；ADR-015 的逐项 `Promise.allSettled` 会把外键冲突变成 N 个 409，需要对 409 单独聚合提示。
- 风险：本地 `users` 表与 Logto 的 `sub` 可能失配（换 IdP、账号重建）→ 引导通道与 `admin:grant` 脚本是逃生舱，验收第 7 条覆盖一半。
- **留给实现**：路由守卫放在 layout 还是每页、`/admin/*` 是否统一 `force-dynamic`——ADR-019 已定「`/api/**` 首行 `requirePermission`」为唯一强制层，页面层守卫只作体验。

## R5　银河首页（P0）

### 目标

`/` 从「迎宾页」升级为产品门面：一眼是银河，唯一主任务是「从一个问题开始」。星图是背景，不是内容——不做数据概览、不做卡片堆叠、不做轮播。

### 用户故事

- 作为使用者，打开项目看到旋转星系与偶发流星，**以便**这不是又一个后台管理系统，而是我的知识宇宙。
- 作为使用者，我想在首页直接输入问题回车，**以便**不用先进工作台再检索。
- 作为使用者，我想从左侧抽屉直达工作台/资产/作品/图谱/检索，**以便**首页就是一个入口而不是中转页。

### 功能点

| 区域 | 行为 |
|------|------|
| 背景 | 深空底色 + 星云 + 螺旋星系缓慢旋转（360°/240s 量级）+ 星点闪烁 + 每 7–12s 偶发 1 颗流星（最多同时 2 颗） |
| 搜索框 | 居中偏上玻璃面板；回车提交跳 `/search?q=…`；`⌘K` / `Ctrl+K` / `/` 聚焦；移动端 `inputmode="search"`。**输入即预览以 R9.5 为准**（ADR-024 第 8 条把内联预览定为本次交付，覆盖本节原先「列 v1.5、本期不做」的旧口径） |
| 左侧抽屉 | 收起为边缘三角把手，展开 320px；条目与导航栏同源（工作台/资产/作品/图谱/检索/管理），管理员才见「管理」；底部放用户区与「本地保存」说明 |
| 未登录 | 搜索框**渲染但禁用**（占位文案「登录后可检索内容」），提交不触发任何请求；显示登录入口；点击搜索框进入登录流程 |
| 与 `/workspace` | `/workspace` 一行不动；`/` 是门面，`/workspace` 是工作区；logo 点击回 `/`，`aria-label` 改为「返回首页」（属行为变更，需写进用户手册） |
| 与主题 | 首页固定深空视觉（品牌场景），前景控件跟随主题语义 token；例外以 `[data-surface="cosmic"]` 显式标注，全站不允许第二处例外 |

### 边界条件（降级与性能）

- `prefers-reduced-motion: reduce`：星系静止、无流星、无闪烁，信息与交互完全不变。
- 图形能力不足时逐级回退：动态星图 → 静态星图 → CSS 渐变 + 少量星点。**任何一级都必须完整可用**。
- `backdrop-filter` 不支持：玻璃面板改实色，边框与高光保留。
- 低性能设备：粒子减半、DPR 上限、帧率上限 30fps。
- 标签页隐藏 → 暂停动画；回来恢复。
- **首屏不阻塞**：搜索框与按钮先渲染可交互，星图延后初始化；首帧前用 CSS 渐变占位避免白闪。
- 移动端（≤560）：主体可窄，搜索框不小于 320；抽屉改 80vw。

### 验收标准

1. 已登录访问 `/`：搜索框可输入，回车跳 `/search?q=xx` 且结果页能出结果；左侧把手可开合，抽屉条目与导航栏**完全一致**（管理员多「管理」一项）。
2. 未登录访问 `/`：搜索框存在但禁用（有「登录后可检索内容」提示）、提交不发起任何检索请求，显示登录入口；点击搜索框进入登录流程。
3. `prefers-reduced-motion: reduce` 下星系静止、无流星，页面主线程占用接近静态页。
4. 切到其它标签页 → 动画暂停（帧数归零），返回后恢复。
5. 首屏：星图初始化完成前，搜索框已可聚焦输入；低端设备（`hardwareConcurrency ≤ 2`）粒子减半且帧率上限 30fps。
6. `/workspace`、`/search`、`/graph`、`/admin` 回归无变化；点 logo 回 `/`，`aria-label` 为「返回首页」。

### 依赖与风险

- 依赖 R6 的语义 token（至少第 0/1 批完成）与导航项抽成单一来源（ADR-018 第 4 条）；否则抽屉与导航栏会各写一套。
- 风险：星图常驻动画拖慢低端机与耗电 → 四级降级链 + DPR 上限 + 隐藏即暂停，验收第 3、4、5 条覆盖。
- 风险：首页成为硬编码颜色重灾区 → 星空色值必须走 `[data-surface="cosmic"]` 的 token 块，纳入与主题同一套审计。
- **技术选型无待定项**：星图由 ADR-018 第 6 条定为 **Canvas 2D 手写**；本文不绑定实现，只约束「首屏可输入、任何降级级别下搜索与抽屉仍完整可用」。

## R6　多主题（P0）

### 目标

在**不改变现有默认观感**的前提下支持 4 套主题，并且首页、工作台、检索、图谱、后台、站内未登录态全部一致。

### 用户故事

- 作为使用者，我想把界面换成深空银河/暖沙/午夜蓝，**以便**长时间使用不刺眼，或配合首页氛围。
- 作为使用者，我切完主题后刷新页面**不希望**先闪一下白色再变深色。
- 作为使用者，我不想因为换了主题就发现某个页面还是旧颜色。

### 功能点

| 项 | 行为 |
|------|------|
| 主题数量 | 4 套：松林绿（默认）、深空银河、暖沙、午夜蓝 |
| 默认主题 | 松林绿，**取值与现有 `globals.css` 完全一致，像素级不变**；首次访问不跟随系统深色 |
| 切换入口 | 左下角头像弹层内 2×2 主题网格（色点 + 名称 + 选中勾），移动端改纵向列表；同一弹层里还有「词表管理」（仅管理员）与退出登录 |
| 生效方式 | 即时生效，不刷新页面，保持滚动位置 |
| 持久化 | 本地保存选择；**不做跨设备/跨浏览器同步**（需用户设置表，v2） |
| 首屏防闪 | 首帧前即应用目标主题，强刷 10 次不出现浅色/白色闪现 |
| 全站一致 | `/`、`/workspace`、`/search`、`/graph`、`/admin` 与站内未登录态同源同变量 |
| 例外 | 首页固定深空视觉，仅此一处例外且需显式标注；其余页面不得出现绕过语义 token 的硬编码颜色 |
| 对比度 | 正文 ≥ 4.5:1；大字 ≥ 3:1；非文字控件边界 ≥ 3:1；焦点环 ≥ 3:1；尊重系统强制颜色模式 |
| 动效 | `prefers-reduced-motion` 下弹层与切换无动画 |

### 边界条件

- 新主题**只能重定义既有语义 token**，不得引入新 token 名（否则每个主题都要维护一遍）。
- 主题只覆盖语义层，品牌色阶是默认主题的实现细节。
- **Logto 托管的登录页不在我们控制范围内**，无法纳入主题；站内未登录态（首页/受保护页跳转前）跟随主题。若要登录页也统一，需在 Logto 控制台改品牌色，属运维动作，不在本需求内。
- 不支持「跟随系统」选项（与「默认必须不变」冲突），v2 再议。

### 验收标准

1. 默认松林绿下，`/`、`/workspace`、`/search`、`/admin` 截图与改版前基线一致（像素差 0）。
2. 切到深空银河后刷新 10 次，无白闪/浅色闪，首帧即目标主题；站内未登录态同样生效。
3. 4 套主题下正文、次级文字、主按钮、危险文字均 ≥ 4.5:1；输入框边框在表面上 ≥ 3:1；焦点环 ≥ 3:1。
4. 切换不刷新、不丢滚动位置；同一会话内 5 个页面全部生效，后台与弹窗无遗漏色块。
5. 主题弹层键盘可完整操作（Tab 进入、方向键移动、Enter 应用、Esc 关闭且焦点回到头像）；`prefers-reduced-motion` 下无过渡。
6. 全站样式审计：除默认主题定义块外不存在裸十六进制色值与 `rgba()` 阴影字面量。

### 依赖与风险

- 依赖 R5 的首页例外标注；两者必须同批收口，否则首页会出现「星空 + 浅色控件」的割裂。
- 风险：改造期间出现「半深半浅」过渡态被当 bug 上报 → 分批落地、每批截图基线、每批独立可回滚。
- 风险：深色下 26 处 `rgba(23,37,31,…)` 阴影变脏黑块 → 阴影全部转语义 token。
- **已定（ADR 裁决 #6）**：防闪只做 `localStorage` + `<head>` 内联同步脚本，**不做 cookie**；读 cookie 会迫使根布局动态渲染。验收只看「首屏不闪」，不约束实现细节。

### R7　分类与标签的统一选择器（P0）

#### 目标

让「分类」「标签」在新建与编辑里是**同一种控件、同一套规则、同一份词表**：只能从已有词条中选，缺的词条通过受控的「自定义」弹窗创建，不能随手输入。分类单选，标签多选。

#### 用户故事

- 作为内容作者，我想在编辑时从候选里选分类，而不是记着逗号分隔手打，**以便**不产生「写作」「写作 」「写作类」三个分裂词。
- 作为内容作者，我想在新建时就填分类，**以便**不用先保存再回头补。
- 作为内容作者，我想在发现没有合适分类时点一下「自定义」新增并自动选中，**以便**不打断当前表单。
- 作为管理员，我想新增词条仍然受长度、查重和数量上限约束，**以便**词表不被临时输入污染。

#### R7.1 已定结论（依 ADR-023 第 1、2 条）

| 问题 | 结论 | 理由 |
|------|------|------|
| 分类单选还是多选 | **单选**：作品**必须有且只有 1 个**；资产**0 或 1 个** | ADR-023 第 2 条：分类是结构字段（作品的生产方式），参与状态流、列表副标题、导出与图谱元数据；多选会让「一个作品同时是文章和课程」成立，现有语义与筛选都会失效。生产库里多值从未出现，收敛无信息损失 |
| 分类上限 | **每对象无上限概念**（单值）；词表启用项沿用 **30 个**上限 | 单值字段不存在「选几个」的问题 |
| 标签上限 | **10 个，不变** | 与 R2、ADR-016、`MAX_TAGS_PER_OBJECT` 一致 |
| 两套数据怎么办 | **合并为一份 `categories` 词表**：原 `work_formats` 原样升级（7 行），自由文本 `categories` 的取值按 R7.6 归并 | 用户认为它们是同一个功能；不合并就必然出现「编辑里的分类」和「系统页的分类」两份数据，需求 2 无法真正成立 |
| 新建作品是否预选 | **默认选中排序第一的启用分类**，用户可改 | 沿用 R1 第 4 条「作品必须有分类，新建默认选第一项」；`uncategorized` 是兜底项、排在末位，不作为默认值（R1 第 5 条） |
| 资产是否可选 | 可选、可清空 | 资产是输入，不承担生产方式 |
| 谁能新增词条 | 任何拥有 `object:write` 的登录账号（与今天「输入新标签即建」等价，但改为显式弹窗） | 不阻断创作；改名、停用、删除、排序仍只给 `vocabulary:category:write` / `vocabulary:tag:write` |
| 新增后是否全局可见 | **是，立即生效**（同一词表，服务端每次读库，无本地副本） | 与 R3「唯一真相」一致 |
| 旧自由文本分类 | 作品：原 `format` 成为唯一分类；原有自由值（与所选分类同名的除外）**逐条转为标签**。资产：`categories[0]` 命中词表则成为分类，其余值转标签 | ADR-023 M1–M3；不丢数据，多余维度由标签承接 |

#### R7.2 模型与规则（行为口径）

1. **一份分类词表 `categories`**：`code`（主键、创建后不可改）、`label`（展示名）、`normalized`（查重键，唯一）、`sort_order`、`state ∈ {active, archived}`、`is_system`。原「形态」只是这份词表在旧版里的叫法，R8 统一改称「分类」。
2. **对象关联**：`objects.category_code`（可空、外键到 `categories.code`）；作品非空由 CHECK 保证。前台一律展示 `label`，接口传递 `code`。
3. **单选语义**：选中新项即替换旧项，不出现「同时选中两个」；作品不可取消为空；资产可清空。
4. **`format` 退场**：`objects.format`、`objects.categories`、`objects.primary_category` 三列删除，**不保留任何别名**。对象 API 字段由 `format` / `categories` / `primaryCategory` 收为 **`category`（code，可 null）**；列表副标题、导出、检索卡片、图谱抽取文本、后台表格全部取 `category`（ADR-023 命名矩阵）。
5. **作品 vs 资产**：作品必须 1 个分类（新建默认第一项，编辑不可清空）；资产 0 或 1 个；两者都可打标签（R2 不变）。
6. **系统分类「未分类」**：保留为兜底项——不可删除、不可停用、不可改名；不出现在筛选下拉（沿用裁决第 7 条）；历史数据缺失时读侧展示它；不做新建默认值。
7. **停用分类**：不出现在候选；已被对象选中的仍显示 label + 「已停用」徽标，允许原样保存（用户不改就仍可提交）；至少保留一个启用分类（沿用 R1）。
8. **归一化与查重**：`normalized = lower(NFKC(连续空白压缩(trim(label))))`；分类名 **1–12 字**（沿用 `MAX_FORMAT_LABEL`），标签名 **1–20 字**；`normalized` 命中即复用，不新建；服务端唯一索引是最终防线，命中 409。
9. **校验只在服务端最终裁决**：前端用同一份 `domain/vocabulary` 规则做即时反馈；未知 `code` / 字符串分类返回 400 `UNKNOWN_CATEGORY`，**不再静默创建**；多值（数组）入参返回 400（接口只接受单个 `category`）。
10. **数量上限反馈**：标签达到 10 个时未选项禁用并给固定文案；接口绕过返回 400 `TAG_LIMIT`；分类词表启用项 30 个为管理侧上限，达到后「自定义」禁用（`CATEGORY_VOCAB_LIMIT`）。

#### R7.3 控件交互（新建与编辑共用 `VocabularyField`）

```
分类 ──────────────────────────────── 已选 1 ───── [＋ 自定义]
[文章 ×]
┌ 搜索分类 ─────────────────┐  ┌──────────┐
│ ● 文章                     │  │ 清空      │  ← 仅资产可用
│ ○ 学习                     │  └──────────┘
│ ○ 课程                     │
│ ○ 直播        （可滚动）    │
└────────────────────────────┘

标签 ──────────────────────────────── 已选 2/10 ── [＋ 自定义]
[工具类 ×] [模板 ×]
┌ 搜索标签 ─────────────────┐  ┌──────────┐
│ ☑ 工具类                   │  │ 清空      │
│ ☑ 模板                     │  └──────────┘
│ ☐ 复盘                     │
└────────────────────────────┘
```

**结构**：标题行（字段名 + 已选计数 + 右侧「自定义」按钮）→ 已选 chips 行（分类最多 1 个；标签按使用顺序，点 `×` 取消）→ 左列候选列表（分类单选、标签复选，含本地搜索框）+ 右列窄操作区（「清空」，无已选时禁用）。移动端：候选与按钮上下堆叠，「自定义」占满一行，点击区 ≥44px。

**候选排序**（分类与标签不同，别混用）：

| 字段 | 排序 |
|------|------|
| 已选项 | 置顶 |
| 未选分类 | 按管理员 `sort_order`（同序按名称） |
| 未选标签 | 按使用次数降序（同次数按名称） |
| 搜索中 | 先「前缀命中」后「包含命中」，组内沿用上面的排序 |

**状态与表现**：

| 状态 | 表现 |
|------|------|
| 默认（作品） | 已选中排序第一的启用分类；候选列表对应项为选中态 |
| 默认（资产） | 无选中；「清空」禁用 |
| 切换（分类） | 点另一项即时替换，chips 只保留 1 个；不发请求 |
| 勾选/取消（标签） | 即时更新 chips 与计数；不发请求 |
| 输入过滤 | **本地过滤，不发请求**；按归一化后的 label 做包含匹配；命中片段高亮；0 条时显示「没有匹配的分类，换个词试试」 |
| 标签达到上限 | 其余项 `disabled`，计数显示「10/10」，提示「最多选 10 个标签」；已选仍可取消 |
| 作品无分类（仅在词表为空或全部停用的情况下出现） | 保存时字段下方报错「作品必须选 1 个分类」，焦点回到该控件；其它已填内容不丢 |
| 清空 | 分类仅资产可清空，作品禁用；标签立即清空不弹确认 |
| 词表为空 | 列表区「还没有分类，点右侧「自定义」新增」；「自定义」高亮；作品此时无法保存 |
| 词表读取失败 | 控件只读并提示「分类读取失败，请刷新重试」，禁止保存（不得静默使用旧值） |
| 无编辑权限（无 `object:write`） | 只读展示已选；隐藏搜索框、「自定义」、「清空」 |
| 已选但已停用 | chip 后加「已停用」徽标；候选列表不出现；可保留保存、可改选其它 |
| 自定义创建达词表上限（启用 30 个） | 「自定义」禁用，提示「分类已有 30 个，请管理员先停用或删除」 |

#### R7.4 「自定义」弹窗

| 项 | 规则 |
|----|------|
| 标题 | 新增分类 / 新增标签 |
| 字段 | 只有「名称」一个必填项；**不提供 code 输入**（自动生成，创建后不可改） |
| 长度 | 分类 1–12 字；标签 1–20 字；超长行内报错，主按钮禁用 |
| 查重 | 输入时按 `normalized` 实时查重；命中已有词条 → 提示「已有「学习」，保存后将直接选中它」，主按钮变「使用已有分类 / 使用已有标签」；点击只做选中，**不写入** |
| 保存 | 成功后关闭弹窗、**自动选中新词条**（分类替换当前值，标签追加）、焦点回到控件；新词条 `state=active`、`is_system=0`、`sort_order` 排在末尾 |
| 失败 | 行内错误并保留输入（重名、超长、词表上限、网络失败）；不关闭弹窗 |
| 权限 | 任何有 `object:write` 的账号可新增；无该权限只读 |
| 全局可见 | 保存成功即写入词表；其它页面 / 其它弹窗下一次读取即可选到，无需刷新缓存 |
| 审计 | 写一条 `vocabulary.category.create` / `vocabulary.tag.create`（`source=inline`，记录名称与操作者），与后台新增同一条路径 |
| 与后台关系 | 「自定义」只是词表新增的快捷入口，**不是**第二套创建逻辑；校验、归一化、上限、审计全部复用同一服务 |

#### R7.5 新建与编辑的一致性（需求 3）

1. **同一组件**：新建弹窗与编辑弹窗都渲染 `VocabularyField`（`mode="category"` 单选 / `mode="tag"` 多选），不得各写一套；分类在标签**上方**。
2. **新建弹窗字段顺序**：类型 → 标题 → **分类** → 标签 → 放在哪里 → 说明；原「作品形态」单选 chip 区整块删除，由分类控件取代。
3. **编辑弹窗字段顺序**：标题 → 描述 → **分类** → 标签 → 优先级；原「分类（逗号分隔）」文本框删除。
4. **同一校验**：必填（作品）、单选值合法性、标签上限 10、长度（12/20）、归一化、未知值拒绝，全部同一份实现；错误文案同源。
5. **同一文案**：字段名、提示、空状态、按钮文字不出现第二套说法（禁止「形态」「标签栏」等别称）。
6. **布局差异只允许两处**：作品分类不可清空并标注「必选」；资产分类标注「选填」且「清空」可用。其余视觉结构一致。

#### R7.6 迁移与兼容（用户预期，对应 ADR-023 第 4 条 M1–M8）

| 场景 | 用户会看到什么 |

### R8　全局命名统一：分类（P0）

#### 目标

同一功能在全站只有一个用户可见名称：**分类**。消除「编辑里叫分类、系统页叫管理形态、新建叫作品形态」的三重分裂。

#### 命名规则（依 ADR-023 第 1 条）

1. **唯一名称**：`分类`。任何用户可见位置（页面标题、导航、字段、表头、按钮、提示、空状态、导出、检索结果、权限名、错误信息、用户手册）一律用「分类」。
2. **禁用词**（UI 文案与 aria-label 中不得出现）：`形态`、`作品形态`、`管理形态`、`类别`、`分类类型`、`格式`（作为分类别称时）。历史变更说明、代码注释不在此限。
3. **「未分类」是分类的一个取值**，不是第二个维度；不要改成「未归类」等新说法。
4. **内部标识同步改名，不保留别名**：表 `categories`、对象列 `objects.category_code`、领域 / API 字段 `category`、权限键 `vocabulary:category:write`、路由 `/admin/vocabulary/categories` 与 `/api/vocabulary/categories`、词表响应键 `categories[]`。**唯一例外**是 RAGFlow 文档元数据的键名 `format`（外部索引契约，避免全量重同步，值改取分类），该键不出现在任何 UI。
5. **文案同源**：新建、编辑、管理页引用同一组文案常量；不允许两个文件各写一份「分类」。
6. **旧地址不消失**：`/admin/vocabulary/formats`、`/api/vocabulary/formats` 一律 308 到新地址（页面地址一年，接口地址一个版本），书签与旧客户端可用。

### R9　首页与全局模糊检索（P0，含首页输入即预览）

#### 目标

搜索框不再只走语义召回：输入关键词即可按**标题、描述、分类、标签**做模糊匹配；语义结果作为补充并入同一列表；RAGFlow 不可用时关键词结果仍然可用；首页输入即出预览。

#### 现状与差距

| 项 | 现状 | 差距 |
|----|------|------|
| 首页搜索框 | 有，未登录禁用；回车跳 `/search?q=` | 没有最少字符限制、没有预览、没有键盘选择 |
| `/search` | 只调 RAGFlow 语义检索，失败整页报错 | 没有关键词层，RAGFlow 挂掉就什么也搜不到 |
| 匹配 | 语义相似度 | 没有子串 / 多词 / 分类标签匹配 |
| 旧项目 | `search.ts` + `search-query.ts` + `command-palette.tsx`：≥2 字、180ms 防抖、字段前缀 / 引号 / `-` / `~` / 布尔、↑↓/Enter | 作为能力参考；采纳其中的确定子集（R9.2），不照搬 `~` 编辑距离与完整布尔表达式 |

#### R9.1 检索范围与匹配（P0，依 ADR-024 第 1、2 条）

| 项 | 规则 |
|----|------|
| 最少字符 | **2 个字符**（`normalizeSearchText` 后）；1 个字符不发请求，`hint` 为「至少输入 2 个字」 |
| 最大长度 | 200 字符，超出返回 400 |
| 归一化 | `normalizeSearchText()`：NFKC（全角转半角）→ 小写 → 连续空白压成一个 → trim；写入与查询用同一函数 |
| 影子列 | `objects.title_norm`、`description_norm` 由仓储在 create / update 时写入，迁移回填；分类 / 标签直接用 `categories.normalized` / `tags.normalized`，不另建列 |
| 匹配方式 | SQLite `instr(lower(col), ?) > 0` 子串匹配，**不用 FTS5**（中文 2 字在 `trigram` 下失效，`unicode61` 把连续汉字当一个 token） |
| 术语切分 | 按空白切词；**多个词之间是 AND**（都命中才算） |
| 单词语义 | 子串包含即命中（不做编辑距离） |
| 字段范围 | **P0：标题、描述、分类名、标签名（SQLite 元数据）**；正文由 RAGFlow 语义层承担，不做本地全文索引 |
| 归属与可见性 | 只返回 `owner_sub = 当前会话`、未软删、默认未归档的对象；与现有语义检索口径一致 |
| 安全 | 值全部参数化绑定；高亮只经 `buildHighlightSnippet()` 输出纯文本片段；不回显数据库原文 |

> 「模糊查询」本轮定义为**子串 + 归一化匹配**，不是错别字容错。错别字由语义检索兜底；编辑距离匹配明确不做（ADR-024 语法表 `~` 行）。

#### R9.2 查询语法（P0，依 ADR-024 第 3 条）

| 语法 | 行为 | 示例 |
|------|------|------|
| 空格分隔 | 全部满足（隐式 AND） | `写作 复盘` |
| `"…"` | 短语，整段子串匹配 | `"个人知识系统"` |
| `title:` / `标题:` | 只匹配标题 | `title:复盘` |
| `desc:` / `描述:` | 只匹配描述 | `desc:模板` |
| `category:` / `分类:` | 只匹配分类名 | `分类:课程` |
| `tag:` / `标签:` | 只匹配标签名 | `标签:工具类` |
| `-词` | 排除（对上述任一字段命中即排除） | `复盘 -草稿` |
| `AND` | 与空格等价，兼容旧习惯 | `写作 AND 复盘` |
| `OR` / 括号 | **不支持**：返回 400 `QUERY_SYNTAX`，`details.position` 给出位置，并给可操作提示（改用两次搜索或标签筛选） | — |
| `NOT` | 等价于 `-` | `复盘 NOT 草稿` |
| `~` | **不支持**：子串匹配已是「模糊」；`~` 按普通字符处理，结果页提示一次「已默认支持模糊匹配，无需 ~」 | — |
| 未知 `x:` | 按普通文本处理（避免把 `http://` 之类误判为字段） | — |

- **语法错误**（未闭合引号、只有 `-`、`OR`、括号）→ 400 `QUERY_SYNTAX`，`details.position` 给出出错位置；`/search` 页在输入框下方显示原文与该位置，客户端先解析、**不发请求**。
- **少于 2 个字符**（归一化后）→ 200 + 空结果 + `hint: "至少输入 2 个字"`；首页预览直接不发请求。
- 搜索框下方放一句「空格分隔多个关键词，结果需同时包含；支持 title: desc: category: tag: 与 -排除」的帮助文字，并可在帮助浮层列出上表；不提供更多语法。

#### R9.3 结果与排序（P0，依 ADR-024 第 4–7 条）

| 层级 | 命中 | 分值 |
|------|------|------|
| T1 | 标题与查询（单词查询）完全相等 | 100 |
| T2 | 标题包含任一词 / 短语 | 80（前缀命中 +10） |
| T3 | 分类名精确相等 70；标签名精确相等 65 | 70 / 65 |
| T4 | 分类名或标签名包含 | 50 |
| T5 | RAGFlow 正文片段命中 | `30 + 15 × similarity`（30–45） |
| T6 | 描述包含 | 20 |

| 项 | 规则 |
|----|------|
| 计分 | 同一对象多条证据取**最高层**计分，`matchedFields` 取并集；同层按 `updatedAt` 倒序，再按 `id` 升序保证稳定 |
| 去重 | **对象级**：一个对象只出一条结果；语义层同对象的多个 chunk 只保留相似度最高的一条，其余数量记入 `chunkCount` |
| 展示方式 | `/search` 为**一个对象级列表**（不分区），每条带来源徽标「标题命中 / 分类命中 / 正文片段」与命中字段；不是两张列表 |
| 摘要 | 词法命中用 `description` 生成摘要（命中词附近截 300 字）；无描述时摘要为「分类：X · 标签：Y」；语义命中沿用 RAGFlow `highlight`；摘要只展示、不参与排序 |
| 条数 | 词法层内部 `LIMIT 501` 判断是否截断，最多返回 **500** 条；`truncated=true` 时提示「结果过多，请加关键词」；首页预览 8 条 |
| 分页 | **P0 不分页**；分页列 P1 |
| 计数 | 响应给出 `total`（去重后对象数）与 `counts: {lexical, semantic, merged}`；页面显示「共 N 条」 |
| 卡片信息 | 类型、库别、分类、标签（最多 3 个）、更新时间、摘要与高亮 |
| 筛选 | 库别沿用；`threshold` **只作用于语义层**，页面上标注「仅影响语义结果」；本轮不加分类 / 标签筛选控件（用 `分类:` / `标签:` 语法） |

#### R9.5 首页输入即预览（P0，本次交付；依 ADR-024 第 8 条）

- **触发**：输入 ≥2 字（归一化后）→ **200ms 防抖**（旧项目 180ms，取 200 减少请求）→ 请求 `mode=lexical&limit=8`；**不调用 RAGFlow**，保证输入不掉帧。
- **取消与乱序**：`AbortController` 取消在途请求；请求序号比对，丢弃过期响应。
- **中文输入法**：`compositionstart` / `compositionend` 期间不触发查询，结束后再防抖；组合中 Enter / ↑ / ↓ 不提交、不选择。
- **键盘**：`↑` / `↓` 移动、`Enter` 打开选中项（无选中则进 `/search?q=`）、`Esc` 先关面板再清空、`⌘K` / `Ctrl+K` / `/` 聚焦；`aria-combobox` + `aria-activedescendant` + `role=listbox/option`。
- **结果项**：标题（命中词高亮）+ 类型 / 分类 / 标签一行 + 页脚「N 条 · 回车查看全部」；面板最大高 `50dvh`（移动端全宽、最大 40vh 滚动）；点击外部关闭。
- **空预览**：「没有匹配的内容，回车查看完整检索」。
- **只列词法结果**：语义结果只在 `/search` 页出现；预览里不出现「语义相关」。
- **未登录**：输入框渲染但禁用（与 R5、裁决第 3 条一致），不发请求。
- 快捷键提示只在非触摸设备显示。

#### R9.6 降级与性能（P0，依 ADR-024 第 6、9、10 条）

- **并行与降级**：词法查询与 RAGFlow 召回并行；RAGFlow **3 秒超时**，超时 / 网络错 / 未建 dataset 分别记 `semantic.status = "timeout" | "unavailable" | "no_dataset"`，词法结果照常返回，页面给中性提示，不报错页。
- **模式**：`mode = hybrid | lexical | semantic`，默认 `hybrid`；`lexical` 完全不请求 RAGFlow，`semantic` 完全不查 SQLite；`threshold` 只作用于语义层，`semantic.thresholdApplied` 说明。
- **响应契约**：`hits[]` 保留现有全部键（不删），新增 `source`、`score`、`matchedFields`、`chunkCount`；`object` 里 `format` 换成 `category`；`total` 改为合并去重后的对象数（`semantic.total` 保留原义）。
- **性能目标**：1 万对象、约 5 万条 `object_tags` 链接下，词法 p95 ≤ **60ms**（服务端）、首页预览 p95 ≤ **30ms**、合并 + 摘要 ≤ 10ms。
- **扩展点**：对象数超过 10 万或词法 p95 超过 150ms 时，另开 ADR 评估 FTS5 `trigram` + 2 字回退 `instr` 的双路径；本期不做。
- **查询开销**：只跑一条候选查询（owner / 未删 / 未归档 + 每个词一个 `instr` 条件），`LIMIT 501`；标签按 `object_id IN (...)` 一次水合，不做 N+1。
- **日志**：只记耗时与结果数，不记录搜索词正文。
